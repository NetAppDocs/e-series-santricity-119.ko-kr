[[what-if-i-dont-see-all-of-my-hardware-components]]
== 모든 하드웨어 구성 요소가 표시되지 않으면 어떻게 해야 하나요?

하드웨어 확인 대화 상자에 모든 하드웨어 구성 요소가 표시되지 않으면 드라이브 셸프가 올바르게 연결되지 않았거나 스토리지 어레이에 호환되지 않는 셸프가 설치되었을 수 있습니다.

모든 드라이브 쉘프가 올바르게 연결되었는지 확인하십시오. 어떤 드라이브 쉘프가 호환되는지 확실하지 않은 경우 기술 지원 부서에 문의하십시오.



[[what-if-i-dont-see-all-of-my-hosts]]
== 모든 호스트가 표시되지 않으면 어떻게 해야 합니까?

연결된 호스트가 표시되지 않으면 자동 감지가 실패했거나 호스트가 잘못 연결되었거나 현재 연결된 호스트가 없는 것입니다.

설정이 완료되면 나중에 호스트를 구성할 수 있습니다. 다음과 같이 수동으로 호스트를 생성할 수 있습니다.

* 메뉴:스토리지[호스트]로 이동하여 호스트를 수동으로 생성하고 적절한 호스트 포트 식별자를 연결할 수 있습니다. 수동으로 생성된 호스트는 *초기 설정* 마법사에도 표시됩니다.
* 대상과 호스트는 호스트 포트 유형(예: iSCSI 또는 NVMe over RoCE)에 맞게 구성되어 있어야 하며, 자동 감지가 작동하려면 스토리지에 대한 세션이 설정되어 있어야 합니다.




[[how-does-identifying-applications-help-me-manage-my-storage-array]]
== 애플리케이션을 식별하면 스토리지 어레이를 관리하는 데 어떤 도움이 됩니까?

애플리케이션을 식별하면 SANtricity System Manager에서 애플리케이션 유형에 따라 스토리지를 최적화하는 볼륨 구성을 자동으로 권장합니다.

애플리케이션별로 볼륨을 최적화하면 데이터 스토리지 작업 효율성을 높일 수 있습니다. I/O 유형, 세그먼트 크기, 컨트롤러 소유권, 읽기 및 쓰기 캐시와 같은 특성이 볼륨 구성에 포함됩니다. 또한 애플리케이션별 및 워크로드별 성능 데이터를 확인하여 애플리케이션 및 관련 워크로드의 지연 시간, IOPS 및 MiB/s를 평가할 수 있습니다.



[[what-is-a-workload]]
== 워크로드란 무엇입니까?

SQL Server 또는 Exchange와 같은 네트워크의 일부 애플리케이션의 경우 해당 애플리케이션에 맞게 스토리지를 최적화하는 워크로드를 정의할 수 있습니다.

워크로드는 애플리케이션을 지원하는 스토리지 개체입니다. 애플리케이션당 하나 이상의 워크로드 또는 인스턴스를 정의할 수 있습니다. 일부 애플리케이션의 경우 시스템은 유사한 기본 볼륨 특성을 가진 볼륨을 포함하도록 워크로드를 구성합니다. 이러한 볼륨 특성은 워크로드가 지원하는 애플리케이션 유형을 기반으로 최적화됩니다. 예를 들어, Microsoft SQL Server 애플리케이션을 지원하는 워크로드를 생성한 다음 해당 워크로드에 대한 볼륨을 생성하면 기본 볼륨 특성이 Microsoft SQL Server를 지원하도록 최적화됩니다.

볼륨 생성 과정에서 시스템은 워크로드 사용 용도에 대한 몇 가지 질문에 답변하도록 요청합니다. 예를 들어 Microsoft Exchange용 볼륨을 생성하는 경우 필요한 사서함 수, 평균 사서함 용량 요구 사항, 데이터베이스 복사본 수 등을 묻습니다. 시스템은 이 정보를 사용하여 최적의 볼륨 구성을 생성하며, 필요에 따라 편집할 수 있습니다.



[[how-do-i-configure-the-delivery-method-for-autosupport]]
== AutoSupport의 전송 방법을 구성하려면 어떻게 해야 합니까?

AutoSupport 제공 방식에 대한 구성 작업에 액세스하려면 메뉴:Support[Support Center]로 이동한 다음 *AutoSupport* 탭을 클릭하십시오.

지원되는 프로토콜은 HTTPS 및 SMTP입니다.



[[how-do-i-know-if-i-should-accept-the-recommended-pool-configuration]]
== 권장 풀 구성을 수락해야 하는지 어떻게 알 수 있습니까?

권장되는 풀 구성을 수락할지 여부는 몇 가지 요인에 따라 달라집니다.

다음 질문에 답하여 요구 사항에 가장 적합한 스토리지 유형을 결정하십시오.

* 가능한 한 가장 큰 풀보다 더 작은 용량의 풀을 여러 개 사용하시겠습니까?
* 풀보다 RAID 볼륨 그룹을 선호하십니까?
* 구성이 자동으로 추천되는 방식보다 수동으로 드라이브를 프로비저닝하는 것을 선호하십니까?


위 질문 중 하나라도 '예'라고 답하셨다면 권장되는 풀 구성을 거부하는 것을 고려하십시오.
