= SANtricity System Manager에서 동기식 미러링이 작동하는 방식
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
동기식 미러링은 데이터 볼륨을 실시간으로 복제하여 지속적인 가용성을 보장합니다.

[NOTE]
====
EF600/EF600C 또는 EF300/EF300C 스토리지 시스템에서는 동기식 미러링을 사용할 수 없습니다.

====
동기식 미러링은 두 스토리지 어레이 중 하나에서 재해가 발생하더라도 중요한 데이터의 복사본을 사용할 수 있도록 함으로써 데이터 손실 제로라는 복구 시점 목표(RPO)를 달성합니다. 기본 볼륨에 쓰기 작업이 수행될 때마다 보조 볼륨에도 쓰기 작업이 수행되므로 복사본은 항상 운영 데이터와 동일합니다. 호스트는 보조 볼륨이 기본 볼륨의 변경 사항으로 성공적으로 업데이트될 때까지 쓰기 작업 성공 확인을 받지 못합니다.

이러한 유형의 미러링은 재해 복구와 같은 비즈니스 연속성 목적에 이상적입니다.



[[synchronous-mirroring-relationship]]
== 동기식 미러링 관계

동기식 미러링 관계는 서로 다른 스토리지 어레이에 있는 기본 볼륨과 보조 볼륨으로 구성됩니다. 기본 볼륨이 포함된 스토리지 어레이는 일반적으로 기본 사이트에 위치하며 활성 호스트에 서비스를 제공합니다. 보조 볼륨이 포함된 스토리지 어레이는 일반적으로 보조 사이트에 위치하며 데이터의 복제본을 저장합니다. 보조 볼륨은 기본 사이트의 완전한 정전, 화재 또는 하드웨어 장애와 같은 이유로 기본 볼륨의 스토리지 어레이를 사용할 수 없는 경우에 사용됩니다.



[[synchronous-mirroring-session]]
== 동기식 미러링 세션

동기식 미러링 구성 프로세스는 볼륨을 쌍으로 구성하는 과정을 포함합니다. 하나의 스토리지 어레이에 있는 기본 볼륨과 다른 스토리지 어레이에 있는 보조 볼륨으로 구성된 미러링 쌍을 생성한 후에는 동기식 미러링을 시작할 수 있습니다. 동기식 미러링 단계는 아래 그림과 같습니다.

image::../media/sam-1130-dwg-sync-mirroring-session.gif[동기식 미러링 세션]

. 호스트에서 쓰기 작업이 들어옵니다.
. 쓰기 작업은 기본 볼륨에 커밋되고, 원격 시스템으로 전파된 다음, 보조 볼륨에 커밋됩니다.
. 운영 볼륨의 스토리지 어레이는 두 쓰기 작업이 모두 성공적으로 완료된 _후에_ 호스트 시스템에 I/O 완료 메시지를 보냅니다.


예약된 용량은 호스트의 수신 쓰기 요청에 대한 정보를 기록하는 데 사용됩니다.

기본 볼륨의 현재 컨트롤러 소유자가 호스트로부터 쓰기 요청을 받으면 컨트롤러는 먼저 기본 볼륨의 예약된 용량에 쓰기 관련 정보를 기록합니다. 그런 다음 데이터를 기본 볼륨에 기록합니다. 이후 컨트롤러는 원격 쓰기 작업을 시작하여 영향을 받는 데이터 블록을 원격 스토리지 어레이의 보조 볼륨으로 복사합니다.

호스트 애플리케이션은 로컬 스토리지 어레이에 쓰기가 완료될 때까지 기다려야 할 뿐만 아니라 네트워크를 통해 원격 스토리지 어레이에도 쓰기가 완료될 때까지 기다려야 하므로, 로컬 I/O 성능을 과도하게 저하시키지 않고 미러 관계를 유지하려면 로컬 스토리지 어레이와 원격 스토리지 어레이 간에 매우 빠른 연결이 필요합니다.



[[disaster-recovery]]
== 재해 복구

동기식 미러링은 데이터가 저장된 위치와 물리적으로 떨어진 곳에 데이터 복사본을 유지합니다. 기본 사이트에서 정전이나 홍수와 같은 재해가 발생할 경우 보조 사이트에서 데이터에 신속하게 접근할 수 있습니다.

동기식 미러링 작업이 진행되는 동안에는 보조 볼륨에서 애플리케이션을 호스팅할 수 없습니다. 따라서 로컬 스토리지 어레이에 재해가 발생할 경우 원격 스토리지 어레이로 페일오버할 수 있습니다. 페일오버를 수행하려면 보조 볼륨을 기본 볼륨으로 승격시켜야 합니다. 그러면 복구 호스트가 새로 승격된 볼륨에 액세스할 수 있게 되어 비즈니스 운영을 계속할 수 있습니다.



[[synchronization-settings]]
== 동기화 설정

미러링된 쌍을 생성할 때 통신 중단 후 재동기화 작업을 완료하기 위해 미러링된 쌍이 사용하는 동기화 우선 순위 및 재동기화 정책도 정의합니다.

두 스토리지 어레이 간의 통신 링크가 작동을 중지하면 호스트는 로컬 스토리지 어레이로부터 계속 승인을 수신하여 액세스 손실을 방지합니다. 통신 링크가 다시 작동하면 복제되지 않은 데이터를 원격 스토리지 어레이에 자동 또는 수동으로 재동기화할 수 있습니다.

데이터가 자동으로 재동기화되는지 여부는 미러링된 쌍의 재동기화 정책에 따라 달라집니다. 자동 재동기화 정책을 사용하면 링크가 다시 작동할 때 미러링된 쌍이 자동으로 재동기화됩니다. 수동 재동기화 정책을 사용하면 통신 문제가 발생한 후 수동으로 동기화를 재개해야 합니다. 수동 재동기화 정책이 권장됩니다.

미러링된 쌍의 동기화 설정은 운영 볼륨이 포함된 스토리지 어레이에서만 편집할 수 있습니다.



[[unsynchronized-data]]
== 동기화되지 않은 데이터

기본 볼륨의 스토리지 어레이가 보조 볼륨에 데이터를 쓸 수 없을 때 기본 볼륨과 보조 볼륨의 동기화가 해제됩니다. 이는 다음과 같은 문제로 인해 발생할 수 있습니다.

* 로컬 스토리지 어레이와 원격 스토리지 어레이 간의 네트워크 문제
* 장애가 발생한 보조 볼륨
* 미러링된 쌍에서 동기화가 수동으로 일시 중단됨




[[orphaned-mirrored-pair]]
== 고아 미러링된 쌍

고아 미러링된 쌍 볼륨은 한쪽(운영 측 또는 보조 측)에서 멤버 볼륨이 제거되었지만 다른 쪽에서는 제거되지 않은 경우 존재합니다.

고립된 미러링된 쌍 볼륨은 어레이 간 통신이 복원되고 미러 구성의 양쪽이 미러 매개변수를 조정할 때 감지됩니다.

미러링된 쌍을 제거하여 고립된 미러링된 쌍 상태를 수정할 수 있습니다.



[[configuration-and-management]]
== 구성 및 관리

두 어레이 간의 미러링을 활성화하고 구성하려면 Unified Manager 인터페이스를 사용해야 합니다. 미러링이 활성화되면 System Manager에서 미러링된 쌍과 동기화 설정을 관리할 수 있습니다.
