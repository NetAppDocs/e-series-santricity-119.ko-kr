[role="lead"]
비동기 미러링을 사용하려는 경우 다음 요구 사항을 염두에 두십시오.



== Unified Manager

두 어레이 간 미러링을 활성화하고 구성하려면 Unified Manager 인터페이스를 사용해야 합니다. Unified Manager는 Web Services Proxy와 함께 호스트 시스템에 설치됩니다.

* Web Services Proxy 서비스가 실행 중이어야 합니다.
* Unified Manager는 HTTPS 연결을 통해 로컬 호스트에서 실행되어야 합니다.
* Unified Manager에 스토리지 어레이에 대한 유효한 SSL 인증서가 표시되어야 합니다. Unified Manager에서 메뉴:인증서[인증서 관리]로 이동하여 자체 서명 인증서를 허용하거나 자체 보안 인증서를 설치할 수 있습니다.




== 스토리지 어레이

* 스토리지 어레이가 두 개 있어야 합니다.
* 각 스토리지 어레이에는 2개의 컨트롤러가 있어야 합니다.
* 두 스토리지 시스템은 Unified Manager에서 검색되어야 합니다.
* 기본 어레이와 보조 어레이의 각 컨트롤러에는 이더넷 관리 포트가 구성되어 있어야 하며 네트워크에 연결되어 있어야 합니다.
* 스토리지 어레이의 최소 펌웨어 버전은 7.84입니다. (각각 다른 OS 버전을 실행할 수 있습니다.)
* 로컬 및 원격 스토리지 어레이의 암호를 알고 있어야 합니다.
* 미러링할 운영 볼륨과 같거나 그보다 큰 보조 볼륨을 생성하려면 원격 스토리지 어레이에 충분한 여유 용량이 있어야 합니다.
* 로컬 및 원격 스토리지 어레이는 Fibre Channel 패브릭 또는 iSCSI 인터페이스를 통해 연결됩니다.




== 지원되는 연결

비동기 미러링은 로컬 스토리지 시스템과 원격 스토리지 시스템 간의 통신에 FC 또는 iSCSI 연결, 혹은 둘 다를 사용할 수 있습니다. 미러 일관성 그룹을 생성할 때 관리자는 원격 스토리지 어레이에 FC와 iSCSI가 모두 연결되어 있는 경우 해당 그룹에 대해 둘 중 하나를 선택할 수 있습니다. 한 채널 유형에서 다른 채널 유형으로의 페일오버는 없습니다.

비동기 미러링은 스토리지 시스템의 호스트 측 I/O 포트를 사용하여 운영 측에서 2차 측으로 미러링된 데이터를 전송합니다.

* *Fibre Channel(FC) 인터페이스를 통한 미러링*
+
스토리지 어레이의 각 컨트롤러는 가장 높은 번호의 FC 호스트 포트를 미러링 작업에 전용으로 사용합니다.

+
컨트롤러에 기본 FC 포트와 호스트 인터페이스 카드(HIC) FC 포트가 모두 있는 경우 번호가 가장 높은 포트가 HIC에 있습니다. 전용 포트에 로그온한 모든 호스트는 로그아웃되며 호스트 로그인 요청은 허용되지 않습니다. 이 포트의 I/O 요청은 미러링 작업에 참여하는 컨트롤러에서만 허용됩니다.

+
전용 미러링 포트는 디렉터리 서비스 및 네임 서비스 인터페이스를 지원하는 FC 패브릭 환경에 연결되어야 합니다. 특히 미러 관계에 참여하는 컨트롤러 간의 연결 옵션으로 FC-AL 및 포인트 투 포인트는 지원되지 않습니다.

* *iSCSI 인터페이스를 통한 미러링*
+
FC와 달리 iSCSI는 전용 포트가 필요하지 않습니다. iSCSI 환경에서 비동기 미러링을 사용할 경우 스토리지 어레이의 프런트엔드 iSCSI 포트를 비동기 미러링 전용으로 할당할 필요가 없습니다. 이러한 포트는 비동기 미러링 트래픽과 호스트-어레이 I/O 연결 모두에 공유됩니다.

+
컨트롤러는 iSCSI 이니시에이터가 세션을 설정하려고 시도하는 원격 스토리지 시스템 목록을 유지 관리합니다. iSCSI 연결을 성공적으로 설정한 첫 번째 포트는 해당 원격 스토리지 어레이와의 모든 후속 통신에 사용됩니다. 통신에 실패하면 사용 가능한 모든 포트를 사용하여 새 세션을 시도합니다.

+
iSCSI 포트는 어레이 수준에서 포트별로 구성됩니다. 구성 메시지 및 데이터 전송을 위한 컨트롤러 간 통신은 다음을 포함한 전역 설정을 사용합니다.

+
** VLAN: 로컬 시스템과 원격 시스템 모두 통신을 위해 동일한 VLAN 설정을 사용해야 합니다
** iSCSI 수신 대기 포트
** 점보 프레임
** 이더넷 우선순위
+
[NOTE]
====
iSCSI 컨트롤러 간 통신에는 관리 이더넷 포트가 아닌 호스트 연결 포트를 사용해야 합니다.

====


+
비동기 미러링은 스토리지 어레이의 호스트 측 I/O 포트를 사용하여 운영 측에서 보조 측으로 미러링된 데이터를 전송합니다. 비동기 미러링은 지연 시간이 길고 비용이 저렴한 네트워크를 위한 것이므로 iSCSI(따라서 TCP/IP 기반) 연결이 적합합니다. iSCSI 환경에서 비동기 미러링을 사용할 경우 비동기 미러링에 사용할 어레이의 프런트엔드 iSCSI 포트를 전용으로 할 필요가 없습니다. 이러한 포트는 비동기 미러 트래픽과 호스트-어레이 I/O 연결 모두에 공유됩니다.



[NOTE]
====
E4000은 iSCSI 프로토콜을 사용하는 동안 비동기 미러링을 지원하지 않습니다.

====


== 미러링된 볼륨 후보

* 비동기 미러링 쌍의 운영 볼륨과 보조 볼륨에서 RAID 레벨, 캐싱 매개변수 및 세그먼트 크기가 서로 다를 수 있습니다.
+

NOTE: EF600 및 EF300 컨트롤러의 경우, 비동기 미러링 쌍의 운영 볼륨과 2차 볼륨은 동일한 프로토콜, 트레이 레벨, 세그먼트 크기, 보안 유형 및 RAID 레벨과 일치해야 합니다. 적격하지 않은 비동기 미러링 쌍은 사용 가능한 볼륨 목록에 표시되지 않습니다.

* 보조 볼륨의 크기는 운영 볼륨의 크기와 최소한 같아야 합니다.
* 볼륨은 하나의 미러 관계에만 참여할 수 있습니다.
* 볼륨 후보는 동일한 데이터 보안 기능을 공유해야 합니다.
+
** 기본 볼륨이 FIPS를 지원하는 경우 보조 볼륨도 FIPS를 지원해야 합니다.
** 운영 볼륨이 FDE를 지원하는 경우 2차 볼륨도 FDE를 지원해야 합니다.
** 기본 볼륨에서 드라이브 보안을 사용하지 않는 경우 보조 볼륨에서도 드라이브 보안을 사용하지 않아야 합니다.


* 운영 볼륨과 2차 볼륨은 동일한 드라이브 유형을 공유해야 합니다. 운영 볼륨과 2차 볼륨 간에 NVMe 및 SAS 드라이브를 혼합하는 것은 지원되지 않습니다.
* 운영 볼륨과 2차 볼륨에는 리소스 파티셔닝이 활성화되어 있으면 안 됩니다.




== 예약된 용량

* 컨트롤러 재설정 및 기타 일시적인 중단으로부터 복구하기 위한 로깅 쓰기 정보를 저장하려면 미러링된 쌍의 운영 볼륨과 2차 볼륨에 대해 예약된 용량 볼륨이 필요합니다.
* 미러링된 쌍의 운영 볼륨과 2차 볼륨 모두에 추가 예약된 용량이 필요하므로 미러 관계에 있는 두 스토리지 어레이 모두에 사용 가능한 여유 용량이 있는지 확인해야 합니다.
* 예약된 용량 볼륨은 연결된 미러 볼륨과 동일한 드라이브 유형을 공유해야 합니다.
+
** 예약된 용량 볼륨이 NVMe 드라이브에 생성되는 경우 해당 미러 볼륨도 NVMe 드라이브에 생성되어야 합니다.
** 예약된 용량 볼륨이 SAS 드라이브에 생성되는 경우 미러 볼륨도 SAS 드라이브에 생성되어야 합니다.






== 드라이브 보안 기능

* 보안 기능을 지원하는 드라이브를 사용하는 경우, 기본 볼륨과 보조 볼륨의 보안 설정이 호환되어야 합니다. 이 제한 사항은 강제 적용되지 않으므로 사용자가 직접 확인해야 합니다.
* 보안 기능을 지원하는 드라이브를 사용하는 경우 기본 볼륨과 보조 볼륨은 동일한 드라이브 유형을 사용해야 합니다. 이 제한 사항은 강제 사항이 아니므로 사용자가 직접 확인해야 합니다.
* Data Assurance(DA)를 사용하는 경우 운영 볼륨과 2차 볼륨의 DA 설정이 동일해야 합니다.
