== 비동기 미러링은 동기 미러링과 어떻게 다른가요?

비동기 미러링 기능은 동기 미러링 기능과 한 가지 중요한 차이점이 있습니다. 특정 시점의 소스 볼륨 상태를 캡처하고 마지막 이미지 캡처 이후 변경된 데이터만 복사합니다.

동기식 미러링에서는 기본 볼륨의 상태가 특정 시점에 캡처되는 것이 아니라 기본 볼륨에서 보조 볼륨으로 수행된 모든 변경 사항을 반영합니다. 이러한 유형의 미러에서는 기본 볼륨에 쓰기가 수행될 때마다 보조 볼륨에 쓰기가 수행되므로 보조 볼륨은 매 순간 기본 볼륨과 동일합니다. 호스트는 기본 볼륨에서 수행된 변경 사항으로 보조 볼륨이 성공적으로 업데이트될 때까지 쓰기가 성공했다는 확인을 받지 못합니다.

비동기 미러링을 사용하는 경우 원격 스토리지 어레이가 로컬 스토리지 어레이와 완전히 동기화되지 않으므로 로컬 스토리지 어레이 손실로 인해 애플리케이션이 원격 스토리지 어레이로 전환해야 하는 경우 일부 트랜잭션이 손실될 수 있습니다.

미러링 기능 비교:

 a|

+
미러링은 모든 호스트 쓰기에서 데이터를 복사하여 자동으로 지속적으로 실행됩니다.

== 선택한 미러링 기능에 액세스할 수 없는 이유는 무엇입니까?

미러링은 SANtricity Unified Manager 인터페이스에서 구성됩니다.

[NOTE]
====
EF600/EF600C 또는 EF300/EF300C 스토리지 시스템에서는 동기식 미러링을 사용할 수 없습니다.

====
두 어레이 간 미러링을 활성화하고 구성하려면 다음을 확인하십시오.

* Web Services Proxy 서비스가 실행 중이어야 합니다. (Unified Manager는 Web Services Proxy와 함께 호스트 시스템에 설치되어 있습니다.)
* Unified Manager는 HTTPS 연결을 통해 로컬 호스트에서 실행되어야 합니다.
* 미러링에 사용할 두 개의 스토리지 어레이는 Unified Manager에서 검색되어야 합니다.
* Unified Manager는 스토리지 어레이에 대한 유효한 SSL 인증서를 보유해야 합니다. 자체 서명 인증서를 사용하거나 Unified Manager에서 CA 서명 인증서를 설치할 수 있습니다.


구성 지침은 다음을 참조하십시오.

* link:../um-manage/create-asynchronous-mirrored-pair-um.html["비동기 미러링 쌍 생성(Unified Manager에서)"]
* link:../um-manage/create-synchronous-mirrored-pair-um.html["동기식 미러링 쌍 생성(Unified Manager에서)"]




== 미러 일관성 그룹을 생성하기 전에 알아야 할 사항은 무엇입니까?

미러 일관성 그룹을 생성하기 전에 다음 지침을 따르십시오.

[NOTE]
====
EF600/EF600C 또는 EF300/EF300C 스토리지 시스템에서는 동기식 미러링을 사용할 수 없습니다.

====
Unified Manager의 미러링된 쌍 생성 마법사에서 일관성 그룹을 생성합니다.

Unified Manager의 경우 다음 요구 사항을 충족해야 합니다.

* Web Services Proxy 서비스가 실행 중이어야 합니다.
* Unified Manager는 HTTPS 연결을 통해 로컬 호스트에서 실행되어야 합니다.
* Unified Manager에 스토리지 어레이에 대한 유효한 SSL 인증서가 표시되어야 합니다. Unified Manager에서 메뉴:인증서[인증서 관리]로 이동하여 자체 서명 인증서를 허용하거나 자체 보안 인증서를 설치할 수 있습니다.


또한 스토리지 어레이에 대해 다음 요구 사항을 충족해야 합니다.

* 두 스토리지 시스템은 Unified Manager에서 검색되어야 합니다.
* 각 스토리지 어레이에는 2개의 컨트롤러가 있어야 합니다.
* 기본 어레이와 보조 어레이의 각 컨트롤러에는 이더넷 관리 포트가 구성되어 있어야 하며 네트워크에 연결되어 있어야 합니다.
* 스토리지 어레이의 최소 펌웨어 버전은 7.84입니다. (각각 다른 OS 버전을 실행할 수 있습니다.)
* 로컬 및 원격 스토리지 어레이의 암호를 알고 있어야 합니다.
* 로컬 및 원격 스토리지 어레이는 Fibre Channel 패브릭 또는 iSCSI 인터페이스를 통해 연결됩니다.




== 비동기 미러링 - 미러링된 쌍을 생성하기 전에 알아야 할 사항은 무엇입니까?

SANtricity Unified Manager 인터페이스에서 미러링된 쌍을 구성한 다음 SANtricity System Manager에서 해당 쌍을 관리합니다.

미러링된 쌍을 생성하기 전에 다음 지침을 따르십시오.

* 스토리지 어레이가 두 개 있어야 합니다.
* 각 스토리지 어레이에는 2개의 컨트롤러가 있어야 합니다.
* 기본 어레이와 보조 어레이의 각 컨트롤러에는 이더넷 관리 포트가 구성되어 있어야 하며 네트워크에 연결되어 있어야 합니다.
* 로컬 및 원격 스토리지 어레이는 Fibre Channel 패브릭 또는 iSCSI 인터페이스를 통해 연결됩니다.
* 스토리지 어레이의 최소 펌웨어 버전은 7.84입니다. (각각 다른 OS 버전을 실행할 수 있습니다.)
* 로컬 및 원격 스토리지 어레이의 암호를 알고 있어야 합니다.
* 미러링할 운영 볼륨과 같거나 그보다 큰 보조 볼륨을 생성하려면 원격 스토리지 어레이에 충분한 여유 용량이 있어야 합니다.
* Web Services Proxy와 Unified Manager를 설치했습니다. Unified Manager 인터페이스에서 미러링된 쌍이 구성됩니다.
* 두 스토리지 어레이가 Unified Manager에서 검색되었습니다.
* 스토리지 어레이에는 하나 이상의 미러 일관성 그룹이 포함되어 있어야 합니다. Unified Manager의 미러링된 쌍 생성 마법사에서 일관성 그룹을 생성합니다.




== 미러링된 쌍 볼륨의 예약된 용량을 늘리기 전에 알아야 할 사항은 무엇입니까?

일반적으로 미러링된 쌍의 예약 용량이 거의 다 되었다는 경고를 받으면 예약 용량을 늘려야 합니다. 예약 용량은 8 GiB 단위로만 늘릴 수 있습니다.

비동기 미러링 작업의 경우 예약 용량은 일반적으로 기본 볼륨의 20%입니다. 다음 조건 중 하나 또는 둘 다에 해당하는 경우 예약 용량을 더 크게 선택하십시오.

* 미러링된 쌍을 장기간 유지하려고 합니다.
* 기본 볼륨에서는 과도한 I/O 활동으로 인해 상당수의 데이터 블록이 변경될 수 있습니다. 과거 성능 데이터 또는 기타 운영 체제 유틸리티를 사용하여 기본 볼륨에 대한 일반적인 I/O 활동을 파악하십시오.


다음 작업 중 하나를 수행하여 미러링된 쌍의 예약된 용량을 늘릴 수 있습니다.

* 미러링된 페어 볼륨의 용량 비율을 조정하려면 menu:Storage[Pools and Volumes Groups]를 선택한 다음 *Reserved Capacity* 탭을 클릭하십시오.
* 풀 또는 볼륨 그룹에서 사용 가능한 여유 용량을 사용하여 새 볼륨을 생성합니다.
+
풀 또는 볼륨 그룹에 사용 가능한 용량이 없는 경우 사용되지 않는 드라이브 형태로 구성되지 않은 용량을 풀 또는 볼륨 그룹에 추가할 수 있습니다.





== 요청한 양만큼 예약된 용량을 늘릴 수 없는 이유는 무엇입니까?

예약된 용량은 4GiB 단위로만 늘릴 수 있습니다.

다음 지침을 검토하십시오.

* 필요한 경우 확장할 수 있도록 풀 또는 볼륨 그룹에 충분한 여유 용량이 있어야 합니다.
+
풀 또는 볼륨 그룹에 사용 가능한 용량이 없는 경우 사용되지 않는 드라이브 형태의 할당되지 않은 용량을 풀 또는 볼륨 그룹에 추가할 수 있습니다.

* 풀 또는 볼륨 그룹의 볼륨은 최적 상태여야 하며 수정 상태가 아니어야 합니다.
* 용량을 늘리려면 사용하려는 풀 또는 볼륨 그룹에 여유 용량이 있어야 합니다.


비동기 미러링 작업의 경우 예약 용량은 일반적으로 기본 볼륨의 20%입니다. 기본 볼륨에 변경 사항이 자주 발생할 것으로 예상되거나 스토리지 객체의 복사 서비스 작업 예상 수명이 매우 길 것으로 예상되는 경우 더 높은 비율을 사용하십시오.



== 이 비율을 변경하는 이유는 무엇입니까?

예약된 용량은 일반적으로 스냅샷 작업의 경우 기본 볼륨의 40%이고 비동기 미러링 작업의 경우 기본 볼륨의 20%입니다.

일반적으로 이 용량이면 충분합니다. 필요한 용량은 기본 볼륨에 대한 I/O 쓰기 빈도 및 크기, 그리고 스토리지 객체의 복사 서비스 작업을 사용할 기간에 따라 달라집니다.

일반적으로 다음 두 가지 조건 중 하나 또는 둘 다 존재하는 경우 예약 용량에 대해 더 큰 비율을 선택하십시오.

* 특정 스토리지 객체의 복사 서비스 작업 수명이 매우 긴 경우.
* 대량의 I/O 작업으로 인해 기본 볼륨의 데이터 블록 중 상당 부분이 변경되는 경우. 과거 성능 데이터 또는 기타 운영 체제 유틸리티를 사용하여 기본 볼륨에 대한 일반적인 I/O 작업을 파악하십시오.




== 예약된 용량 후보가 두 개 이상 표시되는 이유는 무엇입니까?

스토리지 객체에 대해 선택한 용량 비율을 충족하는 볼륨이 풀 또는 볼륨 그룹에 두 개 이상 있는 경우 여러 후보가 표시됩니다.

기본 볼륨에서 복사 서비스 작업을 위해 예약할 물리적 드라이브 공간 비율을 변경하면 권장 후보 목록을 새로 고칠 수 있습니다. 선택 사항에 따라 최적의 후보가 표시됩니다.



== 표에 사용할 수 없음 값이 표시되는 이유는 무엇입니까?

이 표에는 원격 스토리지 어레이에 있는 데이터를 표시할 수 없는 경우 사용 불가 값이 나열됩니다.

원격 스토리지 어레이 데이터를 표시하려면 Unified Manager에서 System Manager를 실행하십시오.



== 내 풀과 볼륨 그룹이 모두 표시되지 않는 이유는 무엇입니까?

비동기 미러링 쌍에 대한 보조 볼륨을 생성하면 시스템은 해당 비동기 미러링 쌍에 사용할 수 있는 모든 풀 및 볼륨 그룹 목록을 표시합니다. 사용할 수 없는 풀 또는 볼륨 그룹은 해당 목록에 표시되지 않습니다.

다음과 같은 이유로 풀 또는 볼륨 그룹이 자격 요건을 충족하지 못할 수 있습니다.

* 풀 또는 볼륨 그룹의 보안 기능이 일치하지 않습니다.
* 풀 또는 볼륨 그룹이 최적이 아닌 상태입니다.
* 풀 또는 볼륨 그룹의 용량이 너무 작습니다.




== 비동기 미러링 - 내 모든 볼륨이 표시되지 않는 이유는 무엇입니까?

미러링된 쌍에 대한 운영 볼륨을 선택할 때 적격 볼륨이 모두 나열됩니다.

사용 자격이 없는 볼륨은 해당 목록에 표시되지 않습니다. 볼륨이 사용 자격이 없는 이유는 다음과 같습니다.

* 볼륨이 최적이 아닙니다.
* 볼륨이 이미 미러링 관계에 참여하고 있습니다.
* 씬 볼륨의 경우 자동 확장을 활성화해야 합니다.



NOTE: EF600 및 EF300 컨트롤러의 경우, 비동기 미러링 쌍의 운영 볼륨과 2차 볼륨은 동일한 프로토콜, 트레이 레벨, 세그먼트 크기, 보안 유형 및 RAID 레벨과 일치해야 합니다. 적격하지 않은 비동기 미러링 쌍은 사용 가능한 볼륨 목록에 표시되지 않습니다.



== 비동기 미러링 - 원격 스토리지 어레이의 모든 볼륨이 표시되지 않는 이유는 무엇입니까?

원격 스토리지 시스템에서 보조 볼륨을 선택할 때 해당 미러링된 쌍에 대해 적격한 모든 볼륨의 목록이 표시됩니다.

사용 자격이 없는 볼륨은 해당 목록에 표시되지 않습니다. 볼륨이 사용 자격이 없는 이유는 다음과 같습니다.

* 볼륨이 최적이 아닙니다.
* 볼륨이 이미 미러링 관계에 참여하고 있습니다.
* 운영 볼륨과 2차 볼륨 간의 씬 볼륨 속성이 일치하지 않습니다.
* Data Assurance(DA)를 사용하는 경우 운영 볼륨과 2차 볼륨의 DA 설정이 동일해야 합니다.
+
** 기본 볼륨이 DA를 사용하는 경우 보조 볼륨도 DA를 사용해야 합니다.
** 기본 볼륨이 DA를 지원하지 않는 경우 보조 볼륨도 DA를 지원하지 않아야 합니다.






== 원격 스토리지 어레이의 IP 주소를 업데이트하는 이유는 무엇입니까?

iSCSI 포트의 IP 주소가 변경되어 로컬 스토리지 어레이가 원격 스토리지 어레이와 통신할 수 없는 경우 원격 스토리지 어레이의 IP 주소를 업데이트해야 합니다.

iSCSI 연결을 사용하여 비동기 미러링 관계를 설정할 때 로컬 및 원격 스토리지 어레이 모두 비동기 미러링 구성에 원격 스토리지 어레이의 IP 주소 레코드를 저장합니다. iSCSI 포트의 IP 주소가 변경되면 해당 포트를 사용하려는 원격 스토리지 어레이에서 통신 오류가 발생합니다.

변경된 IP 주소가 있는 스토리지 어레이는 iSCSI 연결을 통해 미러링하도록 구성된 미러 일관성 그룹과 연결된 각 원격 스토리지 어레이에 메시지를 보냅니다. 이 메시지를 수신한 스토리지 어레이는 원격 대상 IP 주소를 자동으로 업데이트합니다.

변경된 IP 주소가 있는 스토리지 어레이가 원격 스토리지 어레이로 어레이 간 메시지를 전송할 수 없는 경우 시스템에서 연결 문제에 대한 경고를 표시합니다. 로컬 스토리지 어레이와의 연결을 다시 설정하려면 원격 IP 주소 업데이트 옵션을 사용하십시오.
