= NVMe 및 SANtricity 소프트웨어에 대해 알아보십시오
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
일부 컨트롤러에는 패브릭을 통해 NVMe(Non-Volatile Memory Express)를 구현하기 위한 포트가 포함되어 있습니다. NVMe는 호스트와 스토리지 어레이 간의 고성능 통신을 가능하게 합니다.



[[what-is-nvme]]
== NVMe란 무엇입니까?

_NVM_은 "Non-Volatile Memory"의 약자로, 다양한 유형의 스토리지 장치에 사용되는 영구 메모리입니다. _NVMe_(NVM Express)는 NVM 장치와의 고성능 다중 큐 통신을 위해 특별히 설계된 표준화된 인터페이스 또는 프로토콜입니다.



[[what-is-nvme-over-fabrics]]
== NVMe over Fabrics란 무엇입니까?

_NVMe over Fabrics(NVMe-oF)_는 호스트 컴퓨터와 스토리지 간에 네트워크를 통해 NVMe 메시지 기반 명령 및 데이터를 전송할 수 있도록 하는 기술 사양입니다. 호스트는 패브릭을 사용하여 NVMe 스토리지 어레이(_서브시스템_이라고 함)에 액세스할 수 있습니다. NVMe 명령은 호스트 측과 서브시스템 측 모두에서 전송 추상화 계층에서 활성화되고 캡슐화됩니다. 이를 통해 고성능 NVMe 인터페이스를 호스트에서 스토리지까지 엔드 투 엔드로 확장하고 명령 세트를 표준화하고 간소화할 수 있습니다.

NVMe-oF 스토리지는 호스트에 로컬 블록 스토리지 장치로 제공됩니다. 볼륨(_네임스페이스_라고 함)은 다른 블록 스토리지 장치와 마찬가지로 파일 시스템에 마운트할 수 있습니다. 필요에 따라 REST API, SMcli 또는 SANtricity System Manager를 사용하여 스토리지를 프로비저닝할 수 있습니다.



[[what-is-an-nvme-qualified-name-nqn]]
== NVMe Qualified Name(NQN)이란 무엇입니까?

NVMe 정규화 이름(NQN)은 원격 스토리지 대상을 식별하는 데 사용됩니다. 스토리지 어레이의 NVMe 정규화 이름은 항상 서브시스템에서 할당되며 수정할 수 없습니다. 전체 어레이에는 하나의 NVMe 정규화 이름만 존재합니다. NVMe 정규화 이름의 길이는 223자로 제한됩니다. 이는 iSCSI 정규화 이름과 유사합니다.



[[what-is-a-namespace-and-a-namespace-id]]
== 네임스페이스와 네임스페이스 ID란 무엇입니까?

네임스페이스는 SCSI의 논리 유닛에 해당하며 어레이의 볼륨과 관련이 있습니다. 네임스페이스 ID(NSID)는 SCSI의 논리 유닛 번호(LUN)에 해당합니다. 네임스페이스 생성 시 NSID를 생성하며 1에서 255 사이의 값으로 설정할 수 있습니다.



[[what-is-an-nvme-controller]]
== NVMe 컨트롤러란 무엇입니까?

SCSI I_T 넥서스가 호스트의 이니시에이터에서 스토리지 시스템의 타겟까지의 경로를 나타내는 것과 유사하게, 호스트 연결 과정에서 생성된 NVMe 컨트롤러는 호스트와 스토리지 어레이의 네임스페이스 간의 액세스 경로를 제공합니다. 호스트의 NQN과 호스트 포트 식별자를 통해 NVMe 컨트롤러를 고유하게 식별할 수 있습니다. NVMe 컨트롤러는 하나의 호스트에만 연결될 수 있지만, 여러 네임스페이스에 액세스할 수 있습니다.

SANtricity System Manager를 사용하여 어떤 호스트가 어떤 네임스페이스에 액세스할 수 있는지 구성하고 호스트의 네임스페이스 ID를 설정합니다. 그러면 NVMe 컨트롤러가 생성될 때 NVMe 컨트롤러에서 액세스할 수 있는 네임스페이스 ID 목록이 생성되어 허용되는 연결을 구성하는 데 사용됩니다.
