[[what-is-auto-negotiation]]
== 자동 협상이란 무엇입니까?

자동 협상은 네트워크 인터페이스가 자체 연결 매개 변수(속도 및 이중)를 다른 네트워크 인터페이스와 자동으로 조정하는 기능입니다.

관리 포트 구성 시 자동 협상이 일반적으로 권장되는 설정입니다. 그러나 협상이 실패할 경우, 네트워크 인터페이스 설정이 일치하지 않아 네트워크 성능에 심각한 영향을 미칠 수 있습니다. 이러한 상황이 허용되지 않는 경우에는 네트워크 인터페이스 설정을 수동으로 올바른 구성으로 설정해야 합니다. 자동 협상은 컨트롤러의 이더넷 관리 포트에서 수행됩니다. iSCSI 호스트 버스 어댑터는 자동 협상을 수행하지 않습니다.

[NOTE]
====
자동 협상이 실패하면 컨트롤러는 최소 공통 분모인 10BASE-T, 하프 듀플렉스 방식으로 연결을 설정하려고 시도합니다.

====


[[what-is-ipv6-stateless-address-auto-configuration]]
== IPv6 상태 비저장 주소 자동 구성이란 무엇입니까?

상태 비저장 자동 구성 방식을 사용하면 호스트는 서버로부터 주소 및 기타 구성 정보를 얻지 않습니다.

IPv6의 상태 비저장 자동 구성 기능은 링크 로컬 주소, 멀티캐스팅 및 Neighbor Discovery(ND) 프로토콜을 지원합니다. IPv6는 기본 데이터 링크 계층 주소로부터 주소의 인터페이스 ID를 생성할 수 있습니다.

상태 비저장 자동 구성과 상태 저장 자동 구성은 서로를 보완합니다. 예를 들어 호스트는 상태 비저장 자동 구성을 사용하여 자체 주소를 구성하지만 상태 저장 자동 구성을 사용하여 다른 정보를 얻을 수 있습니다. 상태 저장 자동 구성을 통해 호스트는 서버로부터 주소 및 기타 구성 정보를 얻을 수 있습니다. 인터넷 프로토콜 버전 6(IPv6)은 또한 네트워크의 모든 IP 주소를 한 번에 다시 번호를 매기는 방법을 정의합니다. IPv6는 네트워크의 장치가 서버 없이도 자동으로 IP 주소 및 기타 매개변수를 구성할 수 있는 방법을 정의합니다.

디바이스는 상태 비저장 자동 구성을 사용할 때 다음 단계를 수행합니다.

. *링크 로컬 주소 생성* -- 디바이스는 10비트, 그 뒤에 54개의 0, 그리고 64비트 인터페이스 ID로 구성된 링크 로컬 주소를 생성합니다.
. *링크 로컬 주소의 고유성 테스트* -- 노드는 자신이 생성한 링크 로컬 주소가 로컬 네트워크에서 이미 사용 중인지 확인합니다. 노드는 ND 프로토콜을 사용하여 이웃 요청 메시지를 전송합니다. 이에 대한 응답으로 로컬 네트워크는 다른 장치가 해당 링크 로컬 주소를 이미 사용하고 있음을 나타내는 이웃 광고 메시지를 수신 대기합니다. 만약 그렇다면 새로운 링크 로컬 주소를 생성하거나 자동 구성에 실패하고 다른 방법을 사용해야 합니다.
. *링크 로컬 주소 할당* -- 장치가 고유성 테스트를 통과하면 해당 장치는 IP 인터페이스에 링크 로컬 주소를 할당합니다. 링크 로컬 주소는 로컬 네트워크 내 통신에 사용할 수 있지만 인터넷을 통한 통신에는 사용할 수 없습니다.
. *라우터에 연결* -- 노드는 구성을 계속하는 방법에 대한 자세한 정보를 얻기 위해 로컬 라우터에 연결을 시도합니다. 이러한 연결은 라우터에서 주기적으로 전송하는 라우터 광고 메시지를 수신하거나, 다음 단계에 대한 정보를 라우터에 요청하는 특정 라우터 요청 메시지를 전송함으로써 수행됩니다.
. *노드에 대한 지침 제공* -- 라우터는 노드에 자동 구성 진행 방법에 대한 지침을 제공합니다. 또는 라우터는 호스트에게 전역 인터넷 주소를 확인하는 방법을 알려줍니다.
. *전역 주소 구성* -- 호스트는 전역적으로 고유한 인터넷 주소로 자체 구성됩니다. 이 주소는 일반적으로 라우터가 호스트에 제공하는 네트워크 접두사로 구성됩니다.




[[which-do-i-choose-dhcp-or-manual-configuration]]
== DHCP를 선택해야 할까요, 아니면 수동 구성을 선택해야 할까요?

네트워크 구성의 기본 방법은 DHCP(Dynamic Host Configuration Protocol)입니다. 네트워크에 DHCP 서버가 없는 경우를 제외하고는 항상 이 옵션을 사용하십시오.



[[what-is-a-dhcp-server]]
== DHCP 서버란 무엇입니까?

DHCP(Dynamic Host Configuration Protocol)는 IP(Internet Protocol) 주소 할당 작업을 자동화하는 프로토콜입니다.

TCP/IP 네트워크에 연결된 각 장치에는 고유한 IP 주소가 할당되어야 합니다. 이러한 장치에는 스토리지 어레이의 컨트롤러가 포함됩니다.

DHCP를 사용하지 않는 경우 네트워크 관리자가 이러한 IP 주소를 수동으로 입력합니다. DHCP를 사용하면 클라이언트가 TCP/IP 작업을 시작해야 할 때 주소 정보 요청을 브로드캐스트합니다. DHCP 서버는 요청을 수신하고 임대 기간이라는 지정된 시간 동안 새 주소를 할당한 다음 해당 주소를 클라이언트에 전송합니다. DHCP를 사용하면 장치가 네트워크에 연결할 때마다 다른 IP 주소를 가질 수 있습니다. 일부 시스템에서는 장치가 연결된 상태에서도 장치의 IP 주소가 변경될 수 있습니다.



[[how-do-i-configure-my-dhcp-server]]
== DHCP 서버를 어떻게 구성합니까?

스토리지 어레이의 컨트롤러에 고정 IP(Internet Protocol) 주소를 사용하려면 DHCP(Dynamic Host Configuration Protocol) 서버를 구성해야 합니다.

DHCP 서버에서 할당하는 IP 주소는 일반적으로 동적이며 임대 기간이 만료되면 변경될 수 있습니다. 서버나 라우터와 같은 일부 장치는 고정 주소를 사용해야 합니다. 스토리지 시스템의 컨트롤러 또한 고정 IP 주소가 필요합니다.

고정 주소를 할당하는 방법에 대한 자세한 내용은 DHCP 서버 설명서를 참조하십시오.



[[why-do-i-need-to-change-the-controller-network-configuration]]
== 컨트롤러 네트워크 구성을 변경해야 하는 이유는 무엇입니까?

아웃오브밴드(out-of-band) 관리를 사용할 때는 각 컨트롤러에 대해 네트워크 구성(인터넷 프로토콜(IP) 주소, 서브네트워크 마스크(서브넷 마스크) 및 게이트웨이)을 설정해야 합니다.

DHCP(Dynamic Host Configuration Protocol) 서버를 사용하여 네트워크 구성을 설정할 수 있습니다. DHCP 서버를 사용하지 않는 경우 네트워크 구성을 수동으로 입력해야 합니다.



[[where-do-i-get-the-network-configuration]]
== 네트워크 구성은 어디에서 얻을 수 있습니까?

네트워크 관리자로부터 인터넷 프로토콜(IP) 주소, 서브네트워크 마스크(서브넷 마스크) 및 게이트웨이 정보를 얻을 수 있습니다.

컨트롤러에서 포트를 구성할 때 이 정보가 필요합니다.



[[what-are-icmp-ping-responses]]
== ICMP PING 응답이란 무엇입니까?

인터넷 제어 메시지 프로토콜(ICMP)은 TCP/IP 제품군의 프로토콜 중 하나입니다.

 `ICMP echo request`와 (`ICMP echo reply` 메시지는 일반적으로  `ping` 메시지라고 합니다.  `Ping`는 시스템 관리자가 네트워크 장치 간의 연결 상태를 수동으로 테스트하고 네트워크 지연 및 패킷 손실을 테스트하는 데 사용하는 문제 해결 도구입니다.  `ping` 명령은 네트워크상의 장치에  `ICMP echo request`를 보내고, 해당 장치는 즉시 (`ICMP echo reply`로 응답합니다. 때때로 회사의 네트워크 보안 정책에 따라 권한이 없는 사람이 장치를 찾기 어렵게 하기 위해 모든 장치에서  `ping` (`ICMP echo reply`를 비활성화해야 하는 경우가 있습니다.



[[when-should-i-refresh-the-port-configuration]]
== 포트 구성을 새로 고쳐야 하는 경우

서버가 수정되거나 업그레이드될 때마다, 그리고 현재 스토리지 어레이와 사용하려는 스토리지 어레이에 관련된 DHCP 정보가 변경될 때마다 DHCP 서버를 새로 고치십시오.

특히, DHCP 서버가 다른 주소를 할당할 것임을 알고 있는 경우 DHCP 서버에서 포트 구성 또는 iSNS 서버를 새로 고치십시오.

[NOTE]
====
포트 구성을 새로 고치면 해당 포트의 모든 iSCSI 연결이 끊어집니다.

====


[[what-should-i-do-after-configuring-the-management-ports]]
== 관리 포트를 구성한 후에는 무엇을 해야 합니까?

스토리지 어레이의 IP 주소를 변경한 경우 SANtricity Unified Manager의 전역 어레이 보기를 업데이트해야 할 수 있습니다.

Unified Manager에서 전역 배열 보기를 업데이트하려면 인터페이스를 열고 menu:Manage[Discover]로 이동하십시오.

SANtricity Storage Manager를 계속 사용하는 경우 EMW(Enterprise Management Window)로 이동하여 새 IP 주소를 제거하고 다시 추가해야 합니다.



[[why-is-the-storage-system-in-non-optimal-mode]]
== 스토리지 시스템이 최적 모드가 아닌 이유는 무엇입니까?

최적화되지 않은 모드의 스토리지 시스템은 잘못된 시스템 구성 상태 때문입니다. 이 상태에도 불구하고 기존 볼륨에 대한 일반 I/O 액세스는 완전히 지원되지만 SANtricity System Manager는 일부 작업을 금지합니다.

스토리지 시스템이 다음과 같은 이유 중 하나로 인해 Invalid System Configuration으로 전환될 수 있습니다.

* 컨트롤러가 규정을 준수하지 못하고 있습니다. 이는 잘못된 하위 모델 ID(SMID) 코드를 가지고 있거나 프리미엄 기능의 제한을 초과했기 때문일 수 있습니다.
* 드라이브 펌웨어 다운로드와 같은 내부 서비스 작업이 진행 중입니다.
* 컨트롤러가 패리티 오류 임계값을 초과하여 잠금 상태가 되었습니다.
* 일반 잠금 상태가 발생했습니다.
