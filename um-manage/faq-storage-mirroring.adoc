이 FAQ는 질문에 대한 빠른 답변을 찾고 있을 때 도움이 될 수 있습니다.



== 미러 일관성 그룹을 생성하기 전에 알아야 할 사항은 무엇입니까?

미러 일관성 그룹을 생성하기 전에 다음 지침을 따르십시오.

Unified Manager의 경우 다음 요구 사항을 충족해야 합니다.

* Web Services Proxy 서비스가 실행 중이어야 합니다.
* Unified Manager는 HTTPS 연결을 통해 로컬 호스트에서 실행되어야 합니다.
* Unified Manager에 스토리지 어레이에 대한 유효한 SSL 인증서가 표시되어야 합니다. Unified Manager에서 메뉴:인증서[인증서 관리]로 이동하여 자체 서명 인증서를 허용하거나 자체 보안 인증서를 설치할 수 있습니다.


또한 스토리지 어레이에 대해 다음 요구 사항을 충족해야 합니다.

* 두 스토리지 시스템은 Unified Manager에서 검색되어야 합니다.
* 각 스토리지 어레이에는 2개의 컨트롤러가 있어야 합니다.
* 기본 어레이와 보조 어레이의 각 컨트롤러에는 이더넷 관리 포트가 구성되어 있어야 하며 네트워크에 연결되어 있어야 합니다.
* 스토리지 어레이의 최소 펌웨어 버전은 7.84입니다. (각각 다른 OS 버전을 실행할 수 있습니다.)
* 로컬 및 원격 스토리지 어레이의 암호를 알고 있어야 합니다.
* 로컬 및 원격 스토리지 어레이는 Fibre Channel 패브릭 또는 iSCSI 인터페이스를 통해 연결됩니다.


[NOTE]
====
EF600/EF600C 또는 EF300/EF300C 스토리지 시스템에서는 동기식 미러링을 사용할 수 없습니다.

====


== 미러링된 쌍을 생성하기 전에 무엇을 알아야 합니까?

미러링된 쌍을 생성하기 전에 다음 지침을 따르십시오.

* 스토리지 어레이가 두 개 있어야 합니다.
* 각 스토리지 어레이에는 2개의 컨트롤러가 있어야 합니다.
* 두 스토리지 시스템은 Unified Manager에서 검색되어야 합니다.
* 기본 어레이와 보조 어레이의 각 컨트롤러에는 이더넷 관리 포트가 구성되어 있어야 하며 네트워크에 연결되어 있어야 합니다.
* 스토리지 어레이의 최소 펌웨어 버전은 7.84입니다. (각각 다른 OS 버전을 실행할 수 있습니다.)
* 로컬 및 원격 스토리지 어레이의 암호를 알고 있어야 합니다.
* 미러링할 운영 볼륨과 같거나 그보다 큰 보조 볼륨을 생성하려면 원격 스토리지 어레이에 충분한 여유 용량이 있어야 합니다.
* 비동기 미러링은 Fibre Channel(FC) 또는 iSCSI 호스트 포트가 있는 컨트롤러에서 지원되며, 동기 미러링은 FC 호스트 포트가 있는 컨트롤러에서만 지원됩니다.


[NOTE]
====
EF600/EF600C 또는 EF300/EF300C 스토리지 시스템에서는 동기식 미러링을 사용할 수 없습니다.

====


== 이 비율을 변경하는 이유는 무엇입니까?

예약된 용량은 일반적으로 비동기식 미러링 작업을 위한 기본 볼륨의 20%입니다. 일반적으로 이 용량이면 충분합니다.

필요한 용량은 기본 볼륨에 대한 I/O 쓰기 빈도 및 크기, 그리고 스토리지 객체의 복사 서비스 작업을 사용할 기간에 따라 달라집니다. 일반적으로 다음 조건 중 하나 또는 둘 다에 해당하는 경우 예약 용량에 더 큰 비율을 할당하는 것이 좋습니다:

* 특정 스토리지 객체의 복사 서비스 작업 수명이 매우 긴 경우.
* 대량의 I/O 작업으로 인해 기본 볼륨의 데이터 블록 중 상당 부분이 변경되는 경우. 과거 성능 데이터 또는 기타 운영 체제 유틸리티를 사용하여 기본 볼륨에 대한 일반적인 I/O 작업을 파악하십시오.




== 예약된 용량 후보가 두 개 이상 표시되는 이유는 무엇입니까?

스토리지 객체에 대해 선택한 용량 비율을 충족하는 볼륨이 풀 또는 볼륨 그룹에 두 개 이상 있는 경우 여러 후보가 표시됩니다.

기본 볼륨에서 복사 서비스 작업을 위해 예약할 물리적 드라이브 공간 비율을 변경하면 권장 후보 목록을 새로 고칠 수 있습니다. 선택 사항에 따라 최적의 후보가 표시됩니다.



== 내 모든 볼륨이 보이지 않는 이유는 무엇인가요?

미러링된 쌍에 대한 운영 볼륨을 선택할 때 적격 볼륨이 모두 나열됩니다.

사용 자격이 없는 볼륨은 해당 목록에 표시되지 않습니다. 볼륨이 사용 자격이 없는 이유는 다음과 같습니다.

* 볼륨이 최적이 아닙니다.
* 볼륨이 이미 미러링 관계에 참여하고 있습니다.
* 동기식 미러링을 사용하려면 미러링된 쌍의 기본 볼륨과 보조 볼륨은 표준 볼륨이어야 합니다. 씬 볼륨이나 스냅샷 볼륨은 사용할 수 없습니다.
* 비동기 미러링의 경우 씬 볼륨에서 자동 확장을 활성화해야 합니다.



NOTE: EF600 및 EF300 컨트롤러의 경우, 비동기 미러링 쌍의 운영 볼륨과 2차 볼륨은 동일한 프로토콜, 트레이 레벨, 세그먼트 크기, 보안 유형 및 RAID 레벨과 일치해야 합니다. 적격하지 않은 비동기 미러링 쌍은 사용 가능한 볼륨 목록에 표시되지 않습니다.



== 원격 스토리지 어레이의 모든 볼륨이 표시되지 않는 이유는 무엇입니까?

원격 스토리지 시스템에서 보조 볼륨을 선택할 때 해당 미러링된 쌍에 대해 적격한 모든 볼륨의 목록이 표시됩니다.

사용 자격이 없는 볼륨은 해당 목록에 표시되지 않습니다. 볼륨이 사용 자격이 없는 이유는 다음과 같습니다.

* 볼륨은 스냅샷 볼륨과 같은 비표준 볼륨입니다.
* 볼륨이 최적이 아닙니다.
* 볼륨이 이미 미러링 관계에 참여하고 있습니다.
* 비동기 미러링의 경우 운영 볼륨과 보조 볼륨 간의 씬 볼륨 속성이 일치하지 않습니다.
* Data Assurance(DA)를 사용하는 경우 운영 볼륨과 2차 볼륨의 DA 설정이 동일해야 합니다.
+
** 기본 볼륨이 DA를 사용하는 경우 보조 볼륨도 DA를 사용해야 합니다.
** 기본 볼륨이 DA를 지원하지 않는 경우 보조 볼륨도 DA를 지원하지 않아야 합니다.


* 비동기 미러링의 경우 운영 볼륨과 2차 볼륨의 드라이브 보안 기능이 동일해야 합니다.
+
** 기본 볼륨이 FIPS를 지원하는 경우 보조 볼륨도 FIPS를 지원해야 합니다.
** 운영 볼륨이 FDE를 지원하는 경우 2차 볼륨도 FDE를 지원해야 합니다.
** 기본 볼륨에서 드라이브 보안을 사용하지 않는 경우 보조 볼륨에서도 드라이브 보안을 사용하지 않아야 합니다.






== 동기화 우선 순위가 동기화 속도에 어떤 영향을 미칩니까?

동기화 우선순위는 시스템 성능에 비해 동기화 활동에 할당되는 처리 시간을 정의합니다.

기본 볼륨의 컨트롤러 소유자는 이 작업을 백그라운드에서 수행합니다. 동시에 컨트롤러 소유자는 기본 볼륨에 대한 로컬 I/O 쓰기와 보조 볼륨에 대한 관련 원격 쓰기를 처리합니다. 재동기화로 인해 컨트롤러 처리 리소스가 I/O 활동에서 다른 곳으로 전환되므로 재동기화가 호스트 애플리케이션의 성능에 영향을 미칠 수 있습니다.

동기화 우선 순위에 소요되는 시간과 동기화 우선 순위가 시스템 성능에 미치는 영향을 확인하려면 다음 지침을 참조하십시오.

다음과 같은 우선순위 비율을 사용할 수 있습니다.

* 최저
* 낮음
* 중간
* 높음
* 최고


가장 낮은 우선순위 속도는 시스템 성능을 지원하지만 재동기화 시간이 더 오래 걸립니다. 가장 높은 우선순위 속도는 재동기화를 지원하지만 시스템 성능이 저하될 수 있습니다.

이 지침은 우선 순위 간의 차이를 대략적으로 나타냅니다.

[cols="45h,~"]
|===
| 전체 동기화의 우선 순위 속도 | 최고 동기화 속도 대비 경과 시간 


 a| 
최저
 a| 
최우선 순위 속도보다 약 8배 정도 오래 걸립니다.



 a| 
낮음
 a| 
최우선 순위 속도보다 약 6배 정도 더 오래 걸립니다.



 a| 
중간
 a| 
최고 우선 순위 속도보다 약 3.5배 더 오래 걸립니다.



 a| 
높음
 a| 
최고 우선 순위 속도보다 약 2배 정도 깁니다.

|===
볼륨 크기와 호스트 I/O 속도 부하는 동기화 시간 비교에 영향을 미칩니다.



== 수동 동기화 정책을 사용하는 것이 권장되는 이유는 무엇입니까?

수동 재동기화를 권장합니다. 데이터 복구를 위한 최상의 기회를 제공하는 방식으로 재동기화 프로세스를 관리할 수 있기 때문입니다.

자동 재동기화 정책을 사용하는 경우, 재동기화 중에 간헐적인 통신 문제가 발생하면 보조 볼륨의 데이터가 일시적으로 손상될 수 있습니다. 재동기화가 완료되면 데이터가 복구됩니다.
