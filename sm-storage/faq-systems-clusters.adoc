[[what-are-hosts-and-host-clusters]]
== 호스트와 호스트 클러스터란 무엇입니까?

호스트는 스토리지 어레이의 볼륨으로 I/O를 전송하는 서버입니다. 호스트 클러스터는 호스트 그룹입니다. 호스트 클러스터를 생성하면 여러 호스트에 동일한 볼륨을 쉽게 할당할 수 있습니다.

호스트는 별도로 정의합니다. 독립적인 개체이거나 호스트 클러스터에 추가될 수 있습니다. 개별 호스트에 볼륨을 할당하거나 호스트가 호스트 클러스터의 일부가 되어 호스트 클러스터의 다른 호스트와 하나 이상의 볼륨에 대한 액세스를 공유할 수 있습니다.

호스트 클러스터는 SANtricity System Manager에서 생성하는 논리적 엔티티입니다. 볼륨을 할당하기 전에 호스트 클러스터에 호스트를 추가해야 합니다.



[[why-would-i-need-to-create-a-host-cluster]]
== 호스트 클러스터를 생성해야 하는 이유는 무엇입니까?

두 대 이상의 호스트가 동일한 볼륨 세트에 대한 액세스를 공유하려면 호스트 클러스터를 생성해야 합니다. 일반적으로 개별 호스트에는 볼륨 액세스를 조정하기 위한 클러스터링 소프트웨어가 설치되어 있습니다.



[[how-do-i-know-which-host-operating-system-type-is-correct]]
== 어떤 호스트 운영 체제 유형이 올바른지 어떻게 알 수 있습니까?

호스트 운영 체제 유형 필드에는 호스트의 운영 체제가 표시됩니다. 드롭다운 목록에서 권장 호스트 유형을 선택할 수 있습니다.

드롭다운 목록에 표시되는 호스트 유형은 스토리지 어레이 모델과 펌웨어 버전에 따라 다릅니다. 최신 버전에서는 가장 일반적인 옵션이 먼저 표시되므로 해당 옵션이 적합할 가능성이 높습니다. 이 목록에 표시된다고 해서 해당 옵션이 완벽하게 지원되는 것은 아닙니다.

[[what-are-hbas-and-adapter-ports]]
== HBA 및 어댑터 포트란 무엇입니까?

호스트 버스 어댑터(HBA)는 호스트에 장착되는 보드로, 하나 이상의 호스트 포트를 포함합니다. 호스트 포트는 호스트 버스 어댑터(HBA)에 있는 포트로, 컨트롤러와의 물리적 연결을 제공하며 I/O 작업에 사용됩니다.

HBA의 어댑터 포트를 호스트 포트라고 합니다. 대부분의 HBA는 하나 또는 두 개의 호스트 포트를 가지고 있습니다. HBA에는 고유한 WWID(World Wide Identifier)가 있으며, 각 HBA 호스트 포트에도 고유한 WWID가 있습니다. 호스트 포트 식별자는 SANtricity System Manager를 통해 호스트를 수동으로 생성할 때 적절한 HBA를 물리적 호스트와 연결하는 데 사용됩니다.



[[how-do-i-match-the-host-ports-to-a-host]]
== 호스트 포트를 호스트와 어떻게 일치시키나요?

호스트를 수동으로 생성하는 경우 먼저 호스트에서 사용 가능한 적절한 호스트 버스 어댑터(HBA) 유틸리티를 사용하여 호스트에 설치된 각 HBA와 연결된 호스트 포트 식별자를 확인해야 합니다.

이 정보를 확보했으면 Create Host 대화 상자에 제공된 목록에서 스토리지 어레이에 로그인한 호스트 포트 식별자를 선택하십시오.

[NOTE]
====
생성하려는 호스트에 적합한 호스트 포트 식별자를 선택했는지 확인하십시오. 잘못된 호스트 포트 식별자를 연결하면 다른 호스트에서 이 데이터에 의도치 않게 접근할 수 있습니다.

====


[[how-do-i-create-chap-secrets]]
== CHAP 암호는 어떻게 생성합니까?

스토리지 어레이에 연결된 iSCSI 호스트에서 CHAP(Challenge Handshake Authentication Protocol) 인증을 설정한 경우 각 iSCSI 호스트에 대해 해당 이니시에이터 CHAP 암호를 다시 입력해야 합니다.

이를 위해 호스트 생성 작업의 일부로 또는 설정 보기/편집 옵션을 통해 System Manager를 사용할 수 있습니다.

CHAP 상호 인증을 사용하는 경우 설정 페이지에서 스토리지 어레이에 대한 타겟 CHAP 암호를 정의하고 각 iSCSI 호스트에 해당 타겟 CHAP 암호를 다시 입력해야 합니다.



[[what-is-the-default-cluster]]
== 기본 클러스터란 무엇입니까?

기본 클러스터는 시스템에서 정의한 엔티티로, 스토리지 어레이에 로그인한 연결되지 않은 호스트 포트 식별자가 기본 클러스터에 할당된 볼륨에 액세스할 수 있도록 합니다. 연결되지 않은 호스트 포트 식별자란 특정 호스트와 논리적으로 연결되어 있지 않지만 물리적으로 호스트에 설치되어 있고 스토리지 어레이에 로그인된 호스트 포트를 의미합니다.

[NOTE]
====
호스트가 스토리지 어레이의 특정 볼륨에 대한 액세스 권한만 갖도록 하려면 기본 클러스터를 사용해서는 _안 됩니다_. 대신 호스트 포트 식별자를 해당 호스트와 연결해야 합니다. 이 작업은 호스트 생성 작업 중에 수동으로 수행할 수 있습니다. 그런 다음 개별 호스트 또는 호스트 클러스터에 볼륨을 할당합니다.

====
기본 클러스터는 외부 스토리지 환경에서 스토리지 어레이에 연결된 모든 호스트와 로그인한 모든 호스트 포트 식별자가 스토리지 어레이 또는 사용자 인터페이스에 호스트를 명시적으로 알리지 않고도 모든 볼륨에 액세스할 수 있도록 허용하는(전체 액세스 모드) 특수한 상황에서_만_ 사용해야 합니다.

초기에는 명령줄 인터페이스(CLI)를 통해 기본 클러스터에만 볼륨을 할당할 수 있습니다. 하지만 기본 클러스터에 볼륨을 하나 이상 할당하면 이 엔티티(기본 클러스터라고 함)가 사용자 인터페이스에 표시되어 이 엔티티를 관리할 수 있습니다.



[[what-is-host-connectivity-reporting]]
== 호스트 연결 보고란 무엇입니까?

호스트 연결 보고 기능이 활성화되면 스토리지 어레이는 컨트롤러와 구성된 호스트 간의 연결을 지속적으로 모니터링하고 연결이 끊어지면 경고를 표시합니다.

케이블이 느슨하거나 손상되었거나 없거나, 또는 호스트에 다른 문제가 있는 경우 연결이 끊어질 수 있습니다. 이러한 상황에서는 시스템에서 Recovery Guru 메시지가 표시될 수 있습니다.

* *호스트 이중화 손실* -- 두 컨트롤러 중 하나라도 호스트와 통신할 수 없는 경우 열립니다.
* *호스트 유형이 잘못되었습니다* -- 스토리지 어레이에 호스트 유형이 잘못 지정되어 페일오버 문제가 발생할 수 있는 경우 이 메시지가 표시됩니다.


컨트롤러 재부팅 시간이 연결 시간 초과보다 오래 걸릴 수 있는 상황에서는 호스트 연결 보고 기능을 비활성화하는 것이 좋습니다. 이 기능을 비활성화하면 Recovery Gurus 메시지가 표시되지 않습니다.

[NOTE]
====
호스트 연결 보고를 비활성화하면 컨트롤러 리소스 사용량을 모니터링하고 균형을 맞추는 자동 로드 밸런싱도 비활성화됩니다. 하지만 호스트 연결 보고를 다시 활성화하더라도 자동 로드 밸런싱 기능은 자동으로 다시 활성화되지 않습니다.

====
