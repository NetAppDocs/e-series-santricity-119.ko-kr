= SANtricity System Manager에서 수동으로 풀을 생성합니다.
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Pool Auto Configuration 기능이 요구 사항을 충족하는 풀을 제공하지 않는 경우 후보 집합에서 수동으로 풀을 생성할 수 있습니다.

풀은 애플리케이션을 호스팅하는 데 사용할 수 있는 개별 볼륨을 생성하는 데 필요한 논리적 스토리지 용량을 제공합니다.

.시작하기 전에
* 동일한 드라이브 유형(HDD 또는 SSD)의 드라이브가 최소 11개 있어야 합니다.
* 셸프 손실 방지 기능을 사용하려면 풀을 구성하는 드라이브가 최소 6개의 서로 다른 드라이브 셸프에 있어야 하며, 단일 드라이브 셸프에 2개 이상의 드라이브가 있어서는 안 됩니다.
* 서랍 손실 방지를 위해서는 풀을 구성하는 드라이브가 최소 5개의 서로 다른 서랍에 위치해야 하며 풀에는 각 서랍에서 동일한 수의 드라이브 쉘프가 포함되어야 합니다.
* EF600 또는 EF300 스토리지 어레이를 구성할 때 각 컨트롤러가 처음 12개 슬롯에 있는 동일한 수의 드라이브와 마지막 12개 슬롯에 있는 동일한 수의 드라이브에 액세스할 수 있는지 확인하십시오. 이 구성은 컨트롤러가 두 드라이브 측 PCIe 버스를 보다 효과적으로 사용하는 데 도움이 됩니다. 현재 System Manager에서는 볼륨 그룹을 생성할 때 고급 기능에서 드라이브를 선택할 수 있습니다. 풀 생성의 경우 스토리지 어레이의 모든 드라이브를 사용하는 것이 좋습니다.


.단계
. 메뉴: 스토리지[풀 및 볼륨 그룹]를 선택합니다.
. 메뉴:생성[풀]을 클릭합니다.
+
풀 생성 대화 상자가 나타납니다.

. 풀의 이름을 입력합니다.
. *선택 사항:* 스토리지 어레이에 두 가지 이상의 드라이브 유형이 있는 경우 사용할 드라이브 유형을 선택하십시오.
+
결과 테이블에는 생성할 수 있는 모든 풀이 나열됩니다.

. 다음 특성을 기준으로 사용할 풀 후보를 선택한 다음 *Create*를 클릭하십시오.
+
[cols="25h,~"]
|===
| 특성 | 사용 


 a| 
여유 용량
 a| 
풀 후보의 사용 가능한 용량을 GiB 단위로 표시합니다. 애플리케이션의 스토리지 요구 사항에 맞는 용량을 가진 풀 후보를 선택하십시오.

보존(스페어) 용량도 풀 전체에 분산되어 있으며 사용 가능한 용량에 포함되지 않습니다.



 a| 
총 드라이브
 a| 
풀 후보에서 사용 가능한 드라이브 수를 보여줍니다.

System Manager는 가능한 한 많은 드라이브를 보존 용량으로 자동 예약합니다(풀의 드라이브 6개당 System Manager는 보존 용량으로 드라이브 1개를 예약함).

드라이브 장애가 발생하면 재구성된 데이터를 보관하는 데 보존 용량이 사용됩니다.



 a| 
드라이브 블록 크기(EF300 및 EF600만 해당)
 a| 
풀에 있는 드라이브가 쓸 수 있는 블록 크기(섹터 크기)를 보여줍니다. 값에는 다음이 포함될 수 있습니다.

** 512 -- 512바이트 섹터 크기
** 4K -- 4,096바이트 섹터 크기.




 a| 
보안 가능
 a| 
이 풀 후보가 FDE(Full Disk Encryption) 드라이브 또는 FIPS(Federal Information Processing Standard) 드라이브 등 보안 기능을 갖춘 드라이브로만 구성되어 있는지 여부를 나타냅니다.

** Drive Security를 사용하여 풀을 보호할 수 있지만, 이 기능을 사용하려면 모든 드라이브가 보안 가능해야 합니다.
** FDE 전용 풀을 생성하려면 보안 기능 열에서 *예 - FDE*를 찾으십시오. FIPS 전용 풀을 생성하려면 *예 - FIPS* 또는 *예 - FIPS(혼합)*를 찾으십시오. "혼합"은 140-2 및 140-3 레벨 드라이브가 혼합되어 있음을 나타냅니다. 이러한 레벨을 혼합하여 사용하는 경우 풀은 더 낮은 보안 레벨(140-2)로 작동하게 됩니다.
** 보안 기능을 갖춘 드라이브와 그렇지 않은 드라이브, 또는 다양한 보안 수준의 드라이브가 혼합된 드라이브로 구성된 풀을 생성할 수 있습니다. 풀의 드라이브에 보안 기능을 갖추지 않은 드라이브가 포함된 경우 해당 풀을 보안 풀로 설정할 수 없습니다.




 a| 
보안을 활성화하시겠습니까?
 a| 
보안 기능을 지원하는 드라이브에서 드라이브 보안 기능을 활성화할 수 있는 옵션을 제공합니다. 풀이 보안 기능을 지원하고 보안 키를 생성한 경우 확인란을 선택하여 보안을 활성화할 수 있습니다.

[NOTE]
====
Drive Security를 활성화한 후 제거하는 유일한 방법은 풀을 삭제하고 드라이브를 지우는 것입니다.

====


 a| 
DA 지원
 a| 
이 풀 후보에 대해 데이터 보증(DA) 기능을 사용할 수 있는지 여부를 나타냅니다. DA는 데이터가 컨트롤러를 거쳐 드라이브로 전송되는 동안 발생할 수 있는 오류를 검사하고 수정합니다.

모든 드라이브가 DA를 지원하는 경우 DA가 활성화됩니다. 볼륨 생성 후 menu:Storage[Volumes > View/Edit Settings > Advanced > Permanently disable data assurance]를 선택하여 DA를 비활성화할 수 있습니다. 볼륨에서 DA를 비활성화하면 다시 활성화할 수 없습니다.



 a| 
Resource Provisioning Capable(EF300 및 EF600만 해당)
 a| 
이 풀 후보에 대해 리소스 프로비저닝을 사용할 수 있는지 여부를 표시합니다. 리소스 프로비저닝은 EF300 및 EF600 스토리지 어레이에서 사용할 수 있는 기능으로, 백그라운드 초기화 프로세스 없이 볼륨을 즉시 사용할 수 있도록 합니다.



 a| 
쉘프 손실 보호
 a| 
쉘프 손실 보호를 사용할 수 있는지 여부를 표시합니다.

쉘프 손실 방지 기능은 단일 드라이브 쉘프와의 통신이 완전히 두절되더라도 풀에 있는 볼륨의 데이터에 대한 접근성을 보장합니다.



 a| 
드로어 손실 방지
 a| 
드로어 손실 방지를 사용할 수 있는지 여부를 표시합니다. 이 기능은 드로어가 포함된 드라이브 쉘프를 사용하는 경우에만 제공됩니다.

드로어 손실 방지 기능은 드라이브 셸프의 단일 드로어와의 통신이 완전히 두절되는 경우에도 풀에 있는 볼륨의 데이터에 대한 접근성을 보장합니다.



 a| 
지원되는 볼륨 블록 크기(EF300 및 EF600만 해당)
 a| 
풀에 있는 볼륨에 대해 생성할 수 있는 블록 크기를 보여줍니다.

** 512n -- 512바이트 네이티브.
** 512e -- 512바이트 에뮬레이션.
** 4K -- 4,096바이트


|===
