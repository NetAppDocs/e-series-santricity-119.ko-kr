= SANtricity 소프트웨어의 볼륨 관련 용어에 대해 알아보십시오
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
스토리지 어레이에 볼륨 관련 용어가 어떻게 적용되는지 알아보십시오.



== 모든 볼륨 유형

[cols="25h,~"]
|===
| 용어 | 설명 


 a| 
할당된 용량
 a| 
할당된 용량은 볼륨 생성 및 복사 서비스 작업에 사용됩니다.

씩 볼륨의 경우 할당된 용량과 보고된 용량이 동일하지만 씬 볼륨의 경우에는 다릅니다. 씩 볼륨의 경우 물리적으로 할당된 공간은 호스트에 보고되는 공간과 같습니다. 씬 볼륨의 경우 보고된 용량은 호스트에 보고되는 용량이고, 할당된 용량은 현재 데이터 쓰기를 위해 할당된 드라이브 공간의 양입니다.



 a| 
애플리케이션
 a| 
애플리케이션은 SQL Server 또는 Exchange와 같은 소프트웨어입니다. 각 애플리케이션을 지원하기 위해 하나 이상의 워크로드를 정의합니다. 일부 애플리케이션의 경우 시스템에서 스토리지를 최적화하는 볼륨 구성을 자동으로 권장합니다. I/O 유형, 세그먼트 크기, 컨트롤러 소유권, 읽기 및 쓰기 캐시와 같은 특성이 볼륨 구성에 포함됩니다.



 a| 
용량
 a| 
용량은 볼륨에 저장할 수 있는 데이터의 양입니다.



 a| 
컨트롤러 소유권
 a| 
컨트롤러 소유권은 해당 볼륨의 소유 또는 기본 컨트롤러로 지정된 컨트롤러를 정의합니다. 볼륨은 해당 볼륨을 "`소유`"하는 기본 컨트롤러(A 또는 B)를 지정할 수 있습니다. 볼륨 소유권은 Automatic Load Balancing 기능을 사용하여 자동으로 조정되며, 워크로드가 컨트롤러 간에 분산될 때 발생하는 로드 밸런싱 문제를 해결합니다. Automatic Load Balancing은 자동화된 I/O 워크로드 밸런싱을 제공하고 호스트에서 들어오는 I/O 트래픽이 두 컨트롤러에 걸쳐 동적으로 관리되고 균형 있게 분산되도록 합니다.



 a| 
동적 캐시 읽기 프리페치
 a| 
동적 캐시 읽기 프리페치를 사용하면 컨트롤러가 드라이브에서 캐시로 데이터 블록을 읽는 동안 추가 순차 데이터 블록을 캐시에 복사할 수 있습니다. 이 캐싱을 통해 향후 데이터 요청을 캐시에서 채울 가능성이 높아집니다. 동적 캐시 읽기 프리페치는 순차 I/O를 사용하는 멀티미디어 애플리케이션에 중요합니다. 캐시로 프리페치되는 데이터의 속도와 양은 호스트 읽기 속도 및 요청 크기에 따라 자동으로 조정됩니다. 임의 액세스로 인해 데이터가 캐시로 프리페치되지 않습니다. 이 기능은 읽기 캐싱이 비활성화된 경우 적용되지 않습니다.

씬 볼륨의 경우 동적 캐시 읽기 프리페치는 항상 비활성화되며 변경할 수 없습니다.



 a| 
여유 용량 영역
 a| 
여유 용량 영역은 볼륨을 삭제하거나 볼륨 생성 시 사용 가능한 여유 용량을 모두 사용하지 않아 발생하는 여유 용량입니다. 하나 이상의 여유 용량 영역이 있는 볼륨 그룹에 볼륨을 생성하면 해당 볼륨의 용량은 해당 볼륨 그룹에서 가장 큰 여유 용량 영역으로 제한됩니다. 예를 들어, 볼륨 그룹의 총 여유 용량이 15GiB이고 가장 큰 여유 용량 영역이 10GiB인 경우 생성할 수 있는 최대 볼륨은 10GiB입니다.

사용 가능한 용량을 통합하면 볼륨 그룹에서 사용 가능한 최대 용량을 기준으로 추가 볼륨을 생성할 수 있습니다.



 a| 
호스트
 a| 
호스트는 스토리지 어레이의 볼륨으로 I/O를 전송하는 서버입니다.



 a| 
호스트 클러스터
 a| 
호스트 클러스터는 호스트 그룹입니다. 호스트 클러스터를 생성하면 여러 호스트에 동일한 볼륨을 쉽게 할당할 수 있습니다.



 a| 
핫 스페어 드라이브
 a| 
핫 스페어 드라이브는 볼륨 그룹에서만 지원됩니다. 핫 스페어 드라이브에는 데이터가 저장되지 않으며, 볼륨 그룹에 포함된 RAID 1, RAID 3, RAID 5 또는 RAID 6 볼륨에서 드라이브 오류가 발생할 경우를 대비한 대기 드라이브 역할을 합니다. 핫 스페어 드라이브는 스토리지 어레이에 추가적인 수준의 이중화를 제공합니다.



 a| 
LUN
 a| 
LUN(논리 장치 번호)은 호스트가 볼륨에 액세스하는 데 사용하는 주소 공간에 할당된 번호입니다. 볼륨은 LUN 형태의 용량으로 호스트에 제공됩니다.

각 호스트는 고유한 LUN 주소 공간을 갖습니다. 따라서 동일한 LUN을 여러 호스트에서 사용하여 서로 다른 볼륨에 액세스할 수 있습니다.



 a| 
미디어 스캔
 a| 
미디어 검사는 드라이브에서 정상적인 읽기 또는 쓰기 작업 중에 오류가 발견되기 전에 드라이브 미디어 오류를 감지하는 방법을 제공합니다. 미디어 검사는 백그라운드 작업으로 수행되며 정의된 사용자 볼륨의 모든 데이터와 중복 정보를 검사합니다.



 a| 
네임스페이스
 a| 
네임스페이스는 블록 액세스용으로 포맷된 NVM 스토리지입니다. 이는 SCSI의 논리 유닛과 유사하며, 스토리지 어레이의 볼륨에 해당합니다.



 a| 
풀
 a| 
풀은 논리적으로 그룹화된 드라이브 집합입니다. 풀을 사용하여 호스트에서 액세스할 수 있는 하나 이상의 볼륨을 생성할 수 있습니다. (볼륨은 풀 또는 볼륨 그룹에서 생성합니다.)



 a| 
풀 또는 볼륨 그룹 용량
 a| 
풀, 볼륨 또는 볼륨 그룹 용량은 스토리지 어레이에서 풀 또는 볼륨 그룹에 할당된 용량입니다. 이 용량은 볼륨을 생성하고 복사 서비스 작업 및 스토리지 객체의 다양한 용량 요구 사항을 충족하는 데 사용됩니다.



 a| 
읽기 캐시
 a| 
읽기 캐시는 드라이브에서 읽어온 데이터를 저장하는 버퍼입니다. 읽기 작업에 필요한 데이터가 이전 작업에서 이미 캐시에 저장되어 있을 수 있으므로 드라이브에 다시 접근할 필요가 없습니다. 데이터는 캐시에서 비워질 때까지 유지됩니다.



 a| 
보고된 용량
 a| 
보고된 용량은 호스트에 보고되고 호스트에서 액세스할 수 있는 용량입니다.

씩 볼륨의 경우 보고된 용량과 할당된 용량이 동일하지만 씬 볼륨의 경우에는 다릅니다. 씩 볼륨의 경우 물리적으로 할당된 공간은 호스트에 보고되는 공간과 같습니다. 씬 볼륨의 경우 보고된 용량은 호스트에 보고되는 용량이고 할당된 용량은 현재 데이터 쓰기를 위해 할당된 드라이브 공간의 양입니다.



 a| 
세그먼트 크기
 a| 
세그먼트는 스토리지 어레이가 스트라이프(RAID 그룹)의 다음 드라이브로 이동하기 전에 드라이브에 저장되는 데이터 양(킬로바이트, KiB)입니다. 세그먼트 크기는 볼륨 그룹의 용량과 같거나 작습니다. 세그먼트 크기는 고정되어 있으며 풀에 대해 변경할 수 없습니다.



 a| 
스트라이핑
 a| 
스트라이핑은 스토리지 어레이에 데이터를 저장하는 방식입니다. 스트라이핑은 데이터 흐름을 특정 크기("블록 크기"라고 함)의 블록으로 나누어 이러한 블록을 드라이브에 하나씩 기록합니다. 이러한 데이터 저장 방식은 여러 물리적 드라이브에 데이터를 분산하여 저장하는 데 사용됩니다. 스트라이핑은 RAID 0과 동의어이며 패리티 없이 RAID 그룹의 모든 드라이브에 데이터를 분산시킵니다.



 a| 
볼륨
 a| 
볼륨은 애플리케이션, 데이터베이스 및 파일 시스템이 데이터를 저장하는 컨테이너입니다. 이는 호스트가 스토리지 어레이의 스토리지에 액세스하기 위해 생성되는 논리적 구성 요소입니다.



 a| 
볼륨 할당
 a| 
볼륨 할당은 호스트 LUN을 볼륨에 할당하는 방식입니다.



 a| 
볼륨 이름
 a| 
볼륨 이름은 볼륨을 생성할 때 할당되는 문자열입니다. 기본 이름을 그대로 사용하거나 볼륨에 저장된 데이터 유형을 나타내는 더 설명적인 이름을 지정할 수 있습니다.



 a| 
볼륨 그룹
 a| 
볼륨 그룹은 공통된 특성을 가진 볼륨들을 담는 컨테이너입니다. 볼륨 그룹은 용량과 RAID 레벨이 정의되어 있습니다. 볼륨 그룹을 사용하여 호스트에서 접근 가능한 하나 이상의 볼륨을 생성할 수 있습니다. (볼륨은 볼륨 그룹 또는 풀에서 생성합니다.)



 a| 
워크로드
 a| 
워크로드는 애플리케이션을 지원하는 스토리지 개체입니다. 애플리케이션당 하나 이상의 워크로드 또는 인스턴스를 정의할 수 있습니다. 일부 애플리케이션의 경우 시스템은 유사한 기본 볼륨 특성을 가진 볼륨을 포함하도록 워크로드를 구성합니다. 이러한 볼륨 특성은 워크로드가 지원하는 애플리케이션 유형을 기반으로 최적화됩니다. 예를 들어, Microsoft SQL Server 애플리케이션을 지원하는 워크로드를 생성한 다음 해당 워크로드에 대한 볼륨을 생성하면 기본 볼륨 특성이 Microsoft SQL Server를 지원하도록 최적화됩니다.



 a| 
쓰기 캐시
 a| 
쓰기 캐시는 호스트에서 드라이브에 아직 기록되지 않은 데이터를 저장하는 버퍼입니다. 데이터는 드라이브에 기록될 때까지 쓰기 캐시에 보관됩니다. 쓰기 캐싱은 I/O 성능을 향상시킬 수 있습니다.



 a| 
미러링을 사용한 쓰기 캐싱
 a| 
미러링을 사용한 쓰기 캐싱은 한 컨트롤러의 캐시 메모리에 기록된 데이터가 다른 컨트롤러의 캐시 메모리에도 기록될 때 발생합니다. 따라서 한 컨트롤러에 장애가 발생하면 다른 컨트롤러가 미처리된 모든 쓰기 작업을 완료할 수 있습니다. 쓰기 캐시 미러링은 쓰기 캐싱이 활성화되어 있고 두 개의 컨트롤러가 있는 경우에만 사용할 수 있습니다. 미러링을 사용한 쓰기 캐싱은 볼륨 생성 시 기본 설정입니다.



 a| 
배터리 없이 쓰기 캐싱
 a| 
배터리 없이 쓰기 캐싱 설정을 사용하면 배터리가 없거나, 고장났거나, 완전히 방전되었거나, 완전히 충전되지 않은 경우에도 쓰기 캐싱을 계속할 수 있습니다. 하지만 전원이 차단될 경우 데이터 손실이 발생할 수 있으므로 배터리 없이 쓰기 캐싱을 선택하는 것은 일반적으로 권장되지 않습니다. 일반적으로 컨트롤러는 배터리가 충전되거나 고장난 배터리가 교체될 때까지 쓰기 캐싱을 일시적으로 비활성화합니다.

|===


== 씬 볼륨에 특화됨

[NOTE]
====
System Manager는 씬 볼륨을 생성하는 옵션을 제공하지 않습니다. 씬 볼륨을 생성하려면 명령줄 인터페이스(CLI)를 사용하십시오.

====
[NOTE]
====
EF600/EF600C 또는 EF300/EF300C 스토리지 시스템에서는 씬 볼륨을 사용할 수 없습니다.

====

|===
| 용어 | 설명 


 a| 
할당된 용량 제한
 a| 
할당된 용량 제한은 씬 볼륨에 대해 할당된 물리적 용량이 증가할 수 있는 상한입니다.



 a| 
기록된 용량
 a| 
기록된 용량은 씬 볼륨에 할당된 예약된 용량에서 기록된 용량의 양입니다.



 a| 
경고 임계값
 a| 
씬 볼륨에 할당된 용량이 꽉 찬 비율(경고 임계값)에 도달하면 경고 임계값 알림이 발생하도록 설정할 수 있습니다.

|===
