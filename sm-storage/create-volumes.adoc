= SANtricity System Manager에서 볼륨을 생성합니다
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
볼륨을 생성하면 애플리케이션별 워크로드에 스토리지 용량을 추가하고, 생성된 볼륨을 특정 호스트 또는 호스트 클러스터에서 사용할 수 있게 됩니다. 또한, 볼륨 생성 순서에서는 생성하려는 각 볼륨에 특정 용량을 할당하는 옵션을 제공합니다.

.이 작업 정보
대부분의 애플리케이션 유형은 기본적으로 사용자 정의 볼륨 구성을 사용합니다. 일부 애플리케이션 유형은 볼륨 생성 시 스마트 구성이 적용됩니다. 예를 들어 Microsoft Exchange 애플리케이션용 볼륨을 생성하는 경우 필요한 사서함 수, 평균 사서함 용량 요구 사항, 데이터베이스 복사본 수를 입력하라는 메시지가 표시됩니다. System Manager는 이 정보를 사용하여 최적의 볼륨 구성을 생성하며, 필요에 따라 편집할 수 있습니다.

볼륨을 생성하는 과정은 여러 단계를 거치는 절차입니다.



== 1단계: 볼륨의 호스트를 선택합니다

볼륨을 생성하면 애플리케이션별 워크로드에 스토리지 용량을 추가하고, 생성된 볼륨을 특정 호스트 또는 호스트 클러스터에서 사용할 수 있게 됩니다. 또한, 볼륨 생성 순서에서는 생성하려는 각 볼륨에 특정 용량을 할당하는 옵션을 제공합니다.

.시작하기 전에
* 호스트 타일 아래에 유효한 호스트 또는 호스트 클러스터가 있습니다.
* 호스트에 대한 호스트 포트 식별자가 정의되었습니다.
* DA 지원 볼륨을 생성하기 전에 사용하려는 호스트 연결이 DA를 지원해야 합니다. 스토리지 어레이의 컨트롤러에 있는 호스트 연결 중 하나라도 DA를 지원하지 않으면 연결된 호스트는 DA 지원 볼륨의 데이터에 액세스할 수 없습니다.


.이 작업 정보
볼륨을 할당할 때 다음 지침을 염두에 두십시오.

* 호스트의 운영 체제는 호스트가 액세스할 수 있는 볼륨 수에 대한 특정 제한을 둘 수 있습니다. 특정 호스트에서 사용할 볼륨을 생성할 때 이러한 제한 사항을 염두에 두십시오.
* 스토리지 어레이의 각 볼륨에 대해 하나의 할당을 정의할 수 있습니다.
* 할당된 볼륨은 스토리지 어레이의 컨트롤러 간에 공유됩니다.
* 호스트 또는 호스트 클러스터는 동일한 논리 장치 번호(LUN)를 두 번 사용하여 볼륨에 액세스할 수 없습니다. 고유한 LUN을 사용해야 합니다.
* 볼륨 생성 프로세스의 속도를 높이려면 호스트 할당 단계를 건너뛰어 새로 생성된 볼륨이 오프라인으로 초기화되도록 할 수 있습니다.


[NOTE]
====
호스트 클러스터의 호스트에 대해 설정된 할당과 충돌하는 볼륨을 호스트 클러스터에 할당하려고 하면 호스트에 볼륨을 할당하는 작업이 실패합니다.

====
.단계
. 메뉴: Storage[Volumes]를 선택합니다.
. 메뉴:생성[볼륨]을 선택합니다.
+
볼륨 생성 대화 상자가 나타납니다.

. 드롭다운 목록에서 볼륨을 할당할 특정 호스트 또는 호스트 클러스터를 선택하거나 나중에 호스트 또는 호스트 클러스터를 할당하도록 선택합니다.
. 선택한 호스트 또는 호스트 클러스터에 대한 볼륨 생성 시퀀스를 계속하려면 *다음*을 클릭하고 <<2단계: 볼륨에 대한 워크로드를 선택합니다>>으로 이동하십시오.
+
작업 부하 선택 대화 상자가 나타납니다.





== 2단계: 볼륨에 대한 워크로드를 선택합니다

Microsoft SQL Server, Microsoft Exchange, 비디오 감시 애플리케이션 또는 VMware와 같은 특정 애플리케이션에 맞게 스토리지 어레이 구성을 사용자 지정하려면 워크로드를 선택하십시오. 이 스토리지 어레이에서 사용하려는 애플리케이션이 목록에 없는 경우 "기타 애플리케이션"을 선택할 수 있습니다.

.이 작업 정보
이 작업에서는 기존 워크로드에 대한 볼륨을 생성하는 방법을 설명합니다.

* _애플리케이션별 워크로드를 사용하여 볼륨을 생성할 때_, 시스템은 애플리케이션 워크로드 I/O와 애플리케이션 인스턴스의 다른 트래픽 간의 경합을 최소화하기 위해 최적화된 볼륨 구성을 권장할 수 있습니다. 권장 볼륨 구성을 검토하고 볼륨 추가/편집 대화 상자를 사용하여 시스템에서 권장하는 볼륨 및 특성을 편집, 추가 또는 삭제할 수 있습니다.
* "기타" 애플리케이션(또는 특정 볼륨 생성 지원이 없는 애플리케이션)을 사용하여 볼륨을 생성할 때는 볼륨 추가/편집 대화 상자를 사용하여 볼륨 구성을 수동으로 지정합니다.


.단계
. 다음 중 하나를 수행합니다.
+
** 기존 워크로드에 대한 볼륨을 생성하려면 *기존 워크로드에 대한 볼륨 생성* 옵션을 선택합니다.
** 지원되는 애플리케이션 또는 "기타" 애플리케이션에 대한 새 워크로드를 정의하려면 *새 워크로드 생성* 옵션을 선택하십시오.
+
*** 드롭다운 목록에서 새 워크로드를 생성할 애플리케이션의 이름을 선택합니다.
+
이 스토리지 어레이에서 사용하려는 애플리케이션이 목록에 없는 경우 "기타" 항목 중 하나를 선택하십시오.

*** 생성하려는 워크로드의 이름을 입력합니다.




. * 다음 * 을 클릭합니다.
. 워크로드가 지원되는 애플리케이션 유형과 연결되어 있는 경우 요청된 정보를 입력하십시오. 그렇지 않으면 <<3단계: 볼륨 추가 또는 편집>>로 이동하십시오.




== 3단계: 볼륨 추가 또는 편집

System Manager는 사용자가 선택한 애플리케이션 또는 워크로드를 기반으로 볼륨 구성을 제안할 수 있습니다. 이 볼륨 구성은 워크로드가 지원하는 애플리케이션 유형에 따라 최적화됩니다. 권장 볼륨 구성을 그대로 사용하거나 필요에 따라 편집할 수 있습니다. "기타" 애플리케이션 중 하나를 선택한 경우 생성할 볼륨과 특성을 수동으로 지정해야 합니다.

.시작하기 전에
* 풀 또는 볼륨 그룹에는 충분한 여유 용량이 있어야 합니다.
* 볼륨 그룹에 허용되는 최대 볼륨 수는 256개입니다.
* 풀에 허용되는 최대 볼륨 수는 스토리지 시스템 모델에 따라 다릅니다.
+
** 2,048개 볼륨(EF600, EF600C 및 E5700 시리즈)
** 1,024개 볼륨(EF300 및 EF300C)
** 512개 볼륨(E4000 및 E2800 시리즈)


* DA(Data Assurance) 지원 볼륨을 생성하려면 사용하려는 호스트 연결이 DA를 지원해야 합니다.
+
.보안 기능 풀 또는 볼륨 그룹 선택
[%collapsible]
====
DA 지원 볼륨을 생성하려면 DA 지원 풀 또는 볼륨 그룹을 선택합니다(풀 및 볼륨 그룹 후보 테이블에서 "DA" 옆의 *Yes* 참조).

DA 기능은 System Manager에서 풀 및 볼륨 그룹 수준으로 제공됩니다. DA 보호는 데이터가 컨트롤러를 통해 드라이브로 전송될 때 발생할 수 있는 오류를 확인하고 수정합니다. 새 볼륨에 대해 DA 지원 풀 또는 볼륨 그룹을 선택하면 오류가 감지되고 수정됩니다.

스토리지 어레이의 컨트롤러에 있는 호스트 연결 중 하나라도 DA를 지원하지 않으면 해당 호스트는 DA가 활성화된 볼륨의 데이터에 액세스할 수 없습니다.

====
* 보안 기능이 활성화된 볼륨을 생성하려면 스토리지 시스템용 보안 키를 생성해야 합니다.
+
.보안 기능 풀 또는 볼륨 그룹 선택
[%collapsible]
====
보안 기능이 활성화된 볼륨을 생성하려면 보안 기능을 지원하는 풀 또는 볼륨 그룹을 선택하십시오(풀 및 볼륨 그룹 후보 표에서 "Secure-capable" 옆에 *Yes*가 있는지 확인하십시오).

드라이브 보안 기능은 System Manager에서 풀 및 볼륨 그룹 수준에서 제공됩니다. 보안 기능이 활성화된 드라이브는 스토리지 어레이에서 물리적으로 분리된 드라이브의 데이터에 대한 무단 액세스를 방지합니다. 보안 기능이 활성화된 드라이브는 고유한 _암호화 키_를 사용하여 쓰기 시 데이터를 암호화하고 읽기 시 데이터를 복호화합니다.

풀 또는 볼륨 그룹에는 보안 기능을 지원하는 드라이브와 지원하지 않는 드라이브가 모두 포함될 수 있지만, 암호화 기능을 사용하려면 모든 드라이브가 보안 기능을 지원해야 합니다.

====
* 리소스 프로비저닝 볼륨을 생성하려면 모든 드라이브가 DULBE(Deallocated or Unwritten Logical Block Error) 옵션이 있는 NVMe 드라이브여야 합니다.


.이 작업 정보
볼륨은 풀 또는 볼륨 그룹에서 생성합니다. 볼륨 추가/편집 대화 상자에는 스토리지 어레이에서 사용 가능한 모든 풀과 볼륨 그룹이 표시됩니다. 각 풀과 볼륨 그룹에 대해 사용 가능한 드라이브 수와 총 여유 용량이 표시됩니다.

일부 애플리케이션 워크로드의 경우, 각 적격 풀 또는 볼륨 그룹에 제안된 볼륨 구성을 기반으로 한 제안 용량과 남은 사용 가능 용량(GiB 단위)이 표시됩니다. 다른 워크로드의 경우, 풀 또는 볼륨 그룹에 볼륨을 추가하고 보고된 용량을 지정하면 제안 용량이 표시됩니다.

.단계
. 기타를 선택했는지 또는 애플리케이션별 워크로드를 선택했는지에 따라 다음 작업 중 하나를 선택하십시오.
+
** *기타* -- 하나 이상의 볼륨을 생성하려는 각 풀 또는 볼륨 그룹에서 *새 볼륨 추가* 를 클릭합니다.
+
.필드 세부 정보
[%collapsible]
====
[cols="25h,~"]
|===
| 필드 | 설명 


 a| 
볼륨 이름
 a| 
볼륨 생성 순서 중에 System Manager에서 볼륨에 기본 이름을 할당합니다. 기본 이름을 그대로 사용하거나 볼륨에 저장된 데이터 유형을 나타내는 보다 설명적인 이름을 제공할 수 있습니다.



 a| 
보고된 용량
 a| 
새 볼륨의 용량과 사용할 용량 단위(MiB, GiB 또는 TiB)를 정의합니다. Thick 볼륨의 경우 최소 용량은 1 MiB이며, 최대 용량은 풀 또는 볼륨 그룹에 있는 드라이브의 개수와 용량에 따라 결정됩니다.

복사 서비스(스냅샷 이미지, 스냅샷 볼륨, 볼륨 복사본 및 원격 미러)에도 스토리지 용량이 필요하다는 점을 명심하십시오. 따라서 모든 용량을 표준 볼륨에 할당하지 마십시오.

풀의 용량은 드라이브 유형에 따라 4GiB 또는 8GiB 단위로 할당됩니다. 4GiB 또는 8GiB의 배수가 아닌 용량은 할당되지만 사용할 수 없습니다. 전체 용량을 사용하려면 4GiB 또는 8GiB 단위로 용량을 지정하십시오. 사용하지 못하는 용량이 있는 경우 해당 용량을 복구하는 유일한 방법은 볼륨 용량을 늘리는 것입니다.



 a| 
볼륨 블록 크기(EF300 및 EF600만 해당)
 a| 
볼륨에 대해 생성할 수 있는 블록 크기를 표시합니다.

*** 512 -- 512바이트
*** 4K -- 4,096바이트




 a| 
세그먼트 크기
 a| 
볼륨 그룹의 볼륨에만 나타나는 세그먼트 크기 설정을 표시합니다. 성능을 최적화하기 위해 세그먼트 크기를 변경할 수 있습니다.

*허용되는 세그먼트 크기 전환* -- System Manager는 허용되는 세그먼트 크기 전환을 결정합니다. 현재 세그먼트 크기에서 부적절한 전환에 해당하는 세그먼트 크기는 드롭다운 목록에서 사용할 수 없습니다. 허용되는 전환은 일반적으로 현재 세그먼트 크기의 두 배 또는 절반입니다. 예를 들어, 현재 볼륨 세그먼트 크기가 32KiB인 경우 새 볼륨 세그먼트 크기는 16KiB 또는 64KiB가 허용됩니다.

*SSD Cache 지원 볼륨* -- SSD Cache 지원 볼륨의 경우 4KiB 세그먼트 크기를 지정할 수 있습니다. 4KiB 세그먼트 크기는 작은 블록 I/O 작업(예: 16KiB 이하의 I/O 블록 크기)을 처리하는 SSD Cache 지원 볼륨에만 선택하십시오. 큰 블록 순차 작업을 처리하는 SSD Cache 지원 볼륨에 4KiB 세그먼트 크기를 선택하면 성능에 영향을 미칠 수 있습니다.

*세그먼트 크기 변경 소요 시간* -- 볼륨의 세그먼트 크기를 변경하는 데 걸리는 시간은 다음 변수에 따라 달라집니다.

*** 호스트의 I/O 로드
*** 볼륨의 수정 우선 순위
*** 볼륨 그룹의 드라이브 수
*** 드라이브 채널 수
*** 스토리지 어레이 컨트롤러의 처리 성능


볼륨의 세그먼트 크기를 변경하면 I/O 성능에 영향을 미치지만 데이터는 계속 사용할 수 있습니다.



 a| 
보안 가능
 a| 
"Secure-capable" 옆에 *예*가 표시되는 경우는 풀 또는 볼륨 그룹의 드라이브가 보안 기능을 지원하는 경우에만 해당됩니다.

드라이브 보안은 스토리지 시스템에서 물리적으로 제거된 드라이브의 데이터에 대한 무단 액세스를 방지합니다. 이 옵션은 드라이브 보안 기능이 활성화되고 스토리지 시스템에 대해 보안 키가 설정된 경우에만 사용할 수 있습니다.

풀 또는 볼륨 그룹에는 보안 기능을 지원하는 드라이브와 지원하지 않는 드라이브가 모두 포함될 수 있지만, 암호화 기능을 사용하려면 모든 드라이브가 보안 기능을 지원해야 합니다.



 a| 
DA
 a| 
"DA" 옆에 *예*가 표시되는 것은 풀 또는 볼륨 그룹의 드라이브가 DA(Data Assurance)를 지원하는 경우에만 해당됩니다.

DA는 전체 스토리지 시스템에서 데이터 무결성을 향상시킵니다. DA를 사용하면 스토리지 어레이가 컨트롤러를 거쳐 드라이브로 데이터가 전송되는 동안 발생할 수 있는 오류를 검사할 수 있습니다. 새 볼륨에 DA를 사용하면 모든 오류를 감지할 수 있습니다.



 a| 
리소스가 프로비저닝되었습니다(EF300 및 EF600에만 해당)
 a| 
"리소스 프로비저닝됨" 옆에 *예*가 표시되는 경우는 드라이브가 이 옵션을 지원하는 경우에만 해당됩니다. 리소스 프로비저닝은 EF300 및 EF600 스토리지 어레이에서 사용할 수 있는 기능으로, 백그라운드 초기화 프로세스 없이 볼륨을 즉시 사용할 수 있도록 합니다.

== 4단계: 볼륨 구성 검토

생성하려는 볼륨의 요약을 검토하고 필요한 변경 사항을 적용하십시오.

.결과
System Manager는 선택한 풀과 볼륨 그룹에 새 볼륨을 생성한 다음 모든 볼륨 테이블에 새 볼륨을 표시합니다.

.완료한 후
* 애플리케이션이 볼륨을 사용할 수 있도록 애플리케이션 호스트에서 필요한 운영 체제 수정을 수행합니다.
* 운영 체제별 유틸리티(타사 업체에서 제공)를 실행한 다음 SMcli 명령 `-identifyDevices`을 실행하여 볼륨 이름과 호스트 스토리지 어레이 이름을 연결합니다.
+
SMcli는 SANtricity System Manager를 통해 직접 사용할 수 있습니다. 다운로드 가능한 SMcli 버전은 E4000, EF600, EF600C, EF300, EF300C, E5700, EF570, E2800 및 EF280 컨트롤러에서 사용할 수 있습니다. SANtricity System Manager에서 SMcli를 다운로드하려면 *Settings* > *System* 및 *Add-ons* > *Command Line Interface*를 선택하십시오.
