= SANtricity System Manager에서 성능 데이터를 해석합니다.
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
성능 데이터는 스토리지 어레이의 성능을 조정하는 데 도움이 될 수 있습니다.

Performance 데이터를 해석할 때는 스토리지 어레이의 성능에 영향을 미치는 여러 요소를 고려해야 합니다. 다음 표는 주요 고려 사항을 설명합니다.

[cols="25h,~"]
|===
| 성능 데이터 | 성능 튜닝에 대한 의미 


 a| 
지연 시간(밀리초 또는 ms)
 a| 
특정 객체의 I/O 활동을 모니터링합니다.

병목 현상을 일으킬 수 있는 객체를 식별합니다.

* 여러 볼륨이 하나의 볼륨 그룹을 공유하는 경우, 드라이브의 순차 성능을 향상시키고 지연 시간을 줄이기 위해 각 볼륨에 별도의 볼륨 그룹이 필요할 수 있습니다.
* 풀을 사용하면 지연 시간이 길어지고 드라이브 간에 작업 부하가 불균등해질 수 있으므로 지연 시간 값의 의미가 줄어들고 일반적으로 더 높아집니다.
* 드라이브 유형과 속도는 지연 시간에 영향을 미칩니다. 무작위 I/O의 경우 회전 속도가 빠른 드라이브일수록 디스크의 여러 위치로 이동하는 데 걸리는 시간이 짧습니다.
* 드라이브 수가 너무 적으면 대기 중인 명령이 많아지고 드라이브가 명령을 처리하는 데 걸리는 시간이 길어져 시스템의 전반적인 지연 시간이 증가합니다.
* I/O가 클수록 데이터 전송에 추가 시간이 소요되므로 지연 시간이 길어집니다.
* 지연 시간이 길다는 것은 I/O 패턴이 무작위적이라는 것을 나타낼 수 있습니다. 무작위 I/O를 사용하는 드라이브는 순차 스트림을 사용하는 드라이브보다 지연 시간이 더 깁니다.
* 공통 볼륨 그룹의 드라이브 또는 볼륨 간 지연 시간 차이는 느린 드라이브를 나타낼 수 있습니다.




 a| 
IOPS
 a| 
초당 입출력 작업 수(IOPS 또는 IOs/sec)에 영향을 미치는 요소는 다음과 같습니다.

* 액세스 패턴(랜덤 또는 순차)
* I/O 크기
* RAID 레벨
* 캐시 블록 크기
* 읽기 캐싱이 활성화되어 있는지 여부
* 쓰기 캐싱이 활성화되어 있는지 여부
* 동적 캐시 읽기 프리페치
* 세그먼트 크기
* 볼륨 그룹 또는 스토리지 어레이의 드라이브 수


캐시 적중률이 높을수록 I/O 속도가 높아집니다. 쓰기 캐싱을 활성화하면 비활성화했을 때보다 쓰기 I/O 속도가 더 높아집니다. 특정 볼륨에 대해 쓰기 캐싱을 활성화할지 여부를 결정할 때는 현재 IOPS와 최대 IOPS를 확인해야 합니다. 순차 I/O 패턴의 경우 임의 I/O 패턴보다 더 높은 속도를 보여야 합니다. I/O 패턴과 관계없이 쓰기 캐싱을 활성화하면 I/O 속도를 최대화하고 애플리케이션 응답 시간을 단축할 수 있습니다.

볼륨의 IOPS 통계에서 세그먼트 크기를 변경하면 성능 향상을 확인할 수 있습니다. 최적의 세그먼트 크기를 결정하기 위해 여러 번 실험해 보거나 파일 시스템 크기 또는 데이터베이스 블록 크기를 사용할 수도 있습니다.



 a| 
MiB/s
 a| 
전송 속도 또는 처리량은 애플리케이션 I/O 크기와 I/O 속도에 따라 결정됩니다. 일반적으로 애플리케이션 I/O 요청이 작으면 전송 속도는 낮아지지만 I/O 속도가 빨라지고 응답 시간이 단축됩니다. 애플리케이션 I/O 요청이 클수록 처리량이 높아집니다.

일반적인 애플리케이션 I/O 패턴을 이해하면 특정 스토리지 어레이에 대한 최대 I/O 전송 속도를 결정하는 데 도움이 될 수 있습니다.



 a| 
CPU
 a| 
이 값은 사용 중인 처리 용량의 백분율입니다.

동일한 유형의 객체에 대해 CPU 사용량에 차이가 있을 수 있습니다. 예를 들어, 한 컨트롤러의 CPU 사용량이 높거나 시간이 지남에 따라 증가하는 반면 다른 컨트롤러의 사용량은 낮거나 안정적일 수 있습니다. 이 경우 CPU 사용량이 낮은 컨트롤러로 하나 이상의 볼륨에 대한 컨트롤러 소유권을 변경하는 것이 좋습니다.

스토리지 어레이 전체의 CPU를 모니터링할 수 있습니다. 애플리케이션 성능이 저하되는 동안 CPU가 시간이 지남에 따라 계속 증가하는 경우 스토리지 어레이를 추가해야 할 수 있습니다. 엔터프라이즈에 스토리지 어레이를 추가하면 허용 가능한 성능 수준에서 애플리케이션 요구 사항을 계속 충족할 수 있습니다.



 a| 
헤드룸
 a| 
헤드룸은 컨트롤러, 컨트롤러 호스트 채널 및 컨트롤러 드라이브 채널의 남은 성능 여유분을 나타냅니다. 이 값은 백분율로 표시되며, 이러한 구성 요소가 제공할 수 있는 최대 성능과 현재 성능 수준 간의 차이를 나타냅니다.

* 컨트롤러의 경우 헤드룸은 최대 가능 IOPS의 백분율입니다.
* 채널의 경우 헤드룸은 최대 처리량 또는 MiB/s의 백분율입니다. 읽기 처리량, 쓰기 처리량 및 양방향 처리량이 계산에 포함됩니다.
