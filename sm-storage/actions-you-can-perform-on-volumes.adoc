= SANtricity System Manager에서 볼륨에 대해 수행할 수 있는 작업
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
볼륨에 대해 용량 증가, 삭제, 복사, 초기화, 재배포, 소유권 변경, 캐시 설정 변경, 미디어 스캔 설정 변경 등 다양한 작업을 수행할 수 있습니다.



== 용량 증대

볼륨의 용량을 확장하는 방법은 두 가지가 있습니다.

* 풀 또는 볼륨 그룹에서 사용 가능한 여유 용량을 사용합니다.
+
볼륨에 용량을 추가하려면 menu:Storage[Pools and Volume Groups > Add Capacity]를 선택하십시오.

* 볼륨의 풀 또는 볼륨 그룹에 할당되지 않은 용량(사용되지 않은 드라이브 형태)을 추가합니다. 풀 또는 볼륨 그룹에 사용 가능한 용량이 없는 경우 이 옵션을 사용하십시오.
+
풀 또는 볼륨 그룹에 할당되지 않은 용량을 추가하려면 menu:Storage[Pools and Volume Groups > Add Capacity]를 선택합니다.

+
풀 또는 볼륨 그룹에 사용 가능한 여유 용량이 없는 경우 볼륨 용량을 늘릴 수 없습니다. 먼저 풀 또는 볼륨 그룹의 크기를 늘리거나 사용하지 않는 볼륨을 삭제해야 합니다.



볼륨 용량을 확장한 후에는 파일 시스템 크기도 수동으로 그에 맞게 늘려야 합니다. 파일 시스템 크기 조정 방법은 사용 중인 파일 시스템에 따라 다릅니다. 자세한 내용은 호스트 운영 체제 설명서를 참조하십시오.



== 삭제

일반적으로 볼륨은 잘못된 매개변수나 용량으로 생성되었거나, 더 이상 스토리지 구성 요구 사항을 충족하지 않거나, 백업 또는 애플리케이션 테스트에 더 이상 필요하지 않은 스냅샷 이미지인 경우 삭제합니다. 볼륨을 삭제하면 풀 또는 볼륨 그룹의 사용 가능한 용량이 증가합니다.

볼륨을 삭제하면 해당 볼륨에 있는 모든 데이터가 손실됩니다. 볼륨을 삭제하면 연결된 스냅샷 이미지, 일정 및 스냅샷 볼륨도 모두 삭제되고 미러링 관계도 해제됩니다.



== 복사

볼륨을 복사하면 동일한 스토리지 어레이에 소스 볼륨과 타겟 볼륨이라는 두 개의 개별 볼륨의 시점 복사본이 생성됩니다. 볼륨 복사는 메뉴:스토리지[볼륨 > 복사 서비스 > 볼륨 복사]를 선택하여 수행할 수 있습니다.



== 초기화

볼륨을 초기화하면 해당 볼륨의 모든 데이터가 삭제됩니다. 볼륨은 처음 생성될 때 자동으로 초기화됩니다. 하지만 Recovery Guru는 특정 장애 상황에서 복구하기 위해 볼륨을 수동으로 초기화할 것을 권장할 수 있습니다. 볼륨을 초기화하면 WWN, 호스트 할당, 할당된 용량 및 예약된 용량 설정이 유지됩니다. 또한 Data Assurance(DA) 설정과 보안 설정도 그대로 유지됩니다.

메뉴:스토리지[볼륨 > 추가 > 볼륨 초기화]를 선택하여 볼륨을 초기화할 수 있습니다.



== 재배포

볼륨을 재분배하여 볼륨을 기본 설정 컨트롤러 소유자로 다시 이동합니다. 일반적으로 다중 경로 드라이버는 호스트와 스토리지 시스템 간의 데이터 경로에 문제가 발생하면 기본 설정 컨트롤러 소유자로부터 볼륨을 이동합니다.

대부분의 호스트 다중 경로 드라이버는 경로상의 각 볼륨에 대해 선호하는 컨트롤러 소유자에게 액세스하려고 시도합니다. 그러나 선호하는 경로를 사용할 수 없게 되면 호스트의 다중 경로 드라이버는 대체 경로로 페일오버합니다. 이 페일오버로 인해 볼륨 소유권이 대체 컨트롤러로 변경될 수 있습니다. 페일오버의 원인을 해결한 후 일부 호스트는 볼륨 소유권을 자동으로 선호하는 컨트롤러 소유자로 되돌릴 수 있지만, 경우에 따라 볼륨을 수동으로 재분배해야 할 수도 있습니다.

메뉴:Storage[Volumes > More > Redistribute volumes]를 선택하여 볼륨을 재배포할 수 있습니다.



== 볼륨 소유권 변경

볼륨의 소유권을 변경하면 해당 볼륨의 기본 컨트롤러 소유권이 변경됩니다. 볼륨의 기본 컨트롤러 소유자는 menu:Storage[Volumes > View/Edit Settings > Advanced tab]에 나열됩니다.

menu:Storage[Volumes > More > Change ownership]를 선택하여 볼륨의 소유권을 변경할 수 있습니다.



=== 미러링 및 볼륨 소유권

미러링된 쌍의 운영 볼륨이 컨트롤러 A의 소유인 경우, 2차 볼륨 또한 원격 스토리지 시스템의 컨트롤러 A의 소유가 됩니다. 운영 볼륨의 소유자를 변경하면 2차 볼륨의 소유자도 자동으로 변경되어 두 볼륨이 동일한 컨트롤러의 소유가 됩니다. 운영 측의 현재 소유권 변경 사항은 2차 측의 해당 현재 소유권 변경 사항에 자동으로 전파됩니다.

미러 일관성 그룹에 로컬 보조 볼륨이 포함되어 있고 컨트롤러 소유권이 변경되면 첫 번째 쓰기 작업 시 보조 볼륨이 자동으로 원래 컨트롤러 소유자에게 다시 전송됩니다. *소유권 변경* 옵션을 사용하여 보조 볼륨의 컨트롤러 소유권을 변경할 수는 없습니다.



=== 볼륨 복사본 및 볼륨 소유권

볼륨 복사본 작업 중에는 동일한 컨트롤러가 소스 볼륨과 타겟 볼륨을 모두 소유해야 합니다. 볼륨 복사본 작업이 시작될 때 두 볼륨의 기본 컨트롤러가 동일하지 않은 경우가 있습니다. 따라서 타겟 볼륨의 소유권이 소스 볼륨의 기본 컨트롤러로 자동으로 이전됩니다. 볼륨 복사본이 완료되거나 중지되면 타겟 볼륨의 소유권이 기본 컨트롤러로 복원됩니다.

볼륨 복사본 작업 중에 소스 볼륨의 소유권이 변경되면 타겟 볼륨의 소유권도 변경됩니다. 특정 운영 체제 환경에서는 I/O 경로를 사용하기 전에 다중 경로 호스트 드라이버를 재구성해야 할 수 있습니다. (일부 다중 경로 드라이버는 I/O 경로를 인식하도록 편집해야 합니다. 자세한 내용은 드라이버 설명서를 참조하십시오.)



== 캐시 설정 변경

캐시 메모리는 컨트롤러에 있는 임시 휘발성 스토리지(RAM) 영역으로, 드라이브 미디어보다 액세스 시간이 빠릅니다. 캐시 메모리를 사용하면 다음과 같은 이유로 전반적인 I/O 성능을 향상시킬 수 있습니다.

* 호스트에서 읽기를 위해 요청된 데이터는 이전 작업에서 이미 캐시에 저장되어 있을 수 있으므로 드라이브 액세스가 필요하지 않습니다.
* 쓰기 데이터는 처음에 캐시에 기록되므로 애플리케이션은 데이터가 드라이브에 기록될 때까지 기다리지 않고 계속 작업을 수행할 수 있습니다.


메뉴: Storage[Volumes > More > Change cache settings]를 선택하여 다음 캐시 설정을 변경하십시오.

* *읽기 및 쓰기 캐싱* -- 읽기 캐시는 드라이브에서 읽어온 데이터를 저장하는 버퍼입니다. 읽기 작업에 필요한 데이터가 이전 작업에서 이미 캐시에 저장되어 있을 수 있으므로 드라이브에 액세스할 필요가 없습니다. 데이터는 플러시될 때까지 읽기 캐시에 유지됩니다.
+
쓰기 캐시는 호스트에서 드라이브에 아직 기록되지 않은 데이터를 저장하는 버퍼입니다. 데이터는 드라이브에 기록될 때까지 쓰기 캐시에 보관됩니다. 쓰기 캐싱은 I/O 성능을 향상시킬 수 있습니다.

* *미러링을 사용한 쓰기 캐싱* -- 미러링을 사용한 쓰기 캐싱은 한 컨트롤러의 캐시 메모리에 기록된 데이터가 다른 컨트롤러의 캐시 메모리에도 기록될 때 발생합니다. 따라서 한 컨트롤러에 장애가 발생하면 다른 컨트롤러가 미처리된 모든 쓰기 작업을 완료할 수 있습니다. 쓰기 캐시 미러링은 쓰기 캐싱이 활성화되어 있고 두 개의 컨트롤러가 있는 경우에만 사용할 수 있습니다. 미러링을 사용한 쓰기 캐싱은 볼륨 생성 시 기본 설정입니다.
* *배터리 없이 쓰기 캐싱* -- 배터리 없이 쓰기 캐싱 설정을 사용하면 배터리가 없거나, 고장났거나, 완전히 방전되었거나, 완전히 충전되지 않은 경우에도 쓰기 캐싱을 계속할 수 있습니다. 배터리 없이 쓰기 캐싱을 선택하는 것은 일반적으로 권장되지 않습니다. 전원이 차단될 경우 데이터가 손실될 수 있기 때문입니다. 일반적으로 배터리가 충전되거나 고장난 배터리가 교체될 때까지 컨트롤러에 의해 쓰기 캐싱이 일시적으로 꺼집니다.
+
이 설정은 쓰기 캐싱을 활성화한 경우에만 사용할 수 있습니다. 씬 볼륨에서는 이 설정을 사용할 수 없습니다.

* *동적 읽기 캐시 프리페치* -- 동적 캐시 읽기 프리페치는 컨트롤러가 드라이브에서 캐시로 데이터 블록을 읽는 동안 추가적인 순차 데이터 블록을 캐시에 복사할 수 있도록 합니다. 이러한 캐싱을 통해 향후 데이터 요청에 캐시에서 데이터를 채울 가능성이 높아집니다. 동적 캐시 읽기 프리페치는 순차 I/O를 사용하는 멀티미디어 애플리케이션에 중요합니다. 캐시에 프리페치되는 데이터의 속도와 양은 호스트 읽기 속도 및 요청 크기에 따라 자동으로 조정됩니다. 임의 액세스 시에는 캐시에 데이터가 프리페치되지 않습니다. 이 기능은 읽기 캐싱이 비활성화된 경우에는 적용되지 않습니다.
+
씬 볼륨의 경우 동적 캐시 읽기 프리페치는 항상 비활성화되며 변경할 수 없습니다.





== 미디어 스캔 설정 변경

미디어 검사는 애플리케이션에서 자주 읽지 않는 디스크 블록의 미디어 오류를 감지하고 복구합니다. 이 검사를 통해 풀 또는 볼륨 그룹의 다른 드라이브에 장애가 발생할 경우 데이터 손실을 방지할 수 있습니다. 장애가 발생한 드라이브의 데이터는 중복 정보와 풀 또는 볼륨 그룹의 다른 드라이브 데이터를 사용하여 재구성됩니다.

미디어 스캔은 스캔할 용량과 스캔 기간을 기준으로 일정한 속도로 지속적으로 실행됩니다. 백그라운드 스캔은 우선 순위가 높은 백그라운드 작업(예: 재구성)에 의해 일시적으로 중단될 수 있지만 동일한 일정한 속도로 재개됩니다.

menu:Storage[Volumes > More > Change media scan settings]를 선택하여 미디어 스캔을 활성화하고 실행 기간을 설정할 수 있습니다.

볼륨 검사는 스토리지 어레이와 해당 볼륨에 대해 미디어 검사 옵션이 활성화된 경우에만 수행됩니다. 해당 볼륨에 대해 중복 검사도 활성화된 경우, 볼륨에 중복성이 있는 경우 해당 볼륨의 중복 정보가 데이터와의 일관성을 검사합니다. 중복 검사를 포함한 미디어 검사는 각 볼륨이 생성될 때 기본적으로 활성화됩니다.

스캔 중 복구 불가능한 미디어 오류가 발생하면 사용 가능한 경우 중복 정보를 사용하여 데이터를 복구합니다. 예를 들어, 최적의 RAID 5 볼륨이나 최적의 RAID 6 볼륨 또는 드라이브 하나만 오류가 발생한 RAID 6 볼륨에서 중복 정보를 사용할 수 있습니다. 중복 정보를 사용하여 복구 불가능한 오류를 복구할 수 없는 경우 해당 데이터 블록이 읽을 수 없는 섹터 로그에 추가됩니다. 복구 가능한 오류와 복구 불가능한 미디어 오류 모두 이벤트 로그에 보고됩니다.

중복성 검사에서 데이터와 중복성 정보 간에 불일치가 발견되면 이벤트 로그에 보고됩니다.
