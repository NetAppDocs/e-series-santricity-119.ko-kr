= SANtricity System Manager의 원격 스토리지 FAQ
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
이 FAQ는 질문에 대한 빠른 답변을 찾고 있을 때 도움이 될 수 있습니다.



== 원격 스토리지 연결을 생성하기 전에 알아야 할 사항은 무엇입니까?

원격 스토리지 기능을 구성하려면 iSCSI를 통해 원격 장치와 타겟 스토리지 시스템을 직접 연결해야 합니다.

iSCSI 시스템 연결을 설정하려면 다음을 참조하십시오.

* link:../sm-hardware/configure-iscsi-ports-hardware.html["iSCSI 포트 구성"]
* https://www.netapp.com/pdf.html?item=/media/28697-tr-4893-deploy.pdf["원격 스토리지 기술 보고서"^]




== 원격 볼륨을 제거하라는 메시지가 표시되는 이유는 무엇입니까?

최대 원격 볼륨 수에 도달하면 스토리지 시스템이 사용되지 않는 원격 볼륨을 자동으로 감지하고 제거하라는 메시지를 표시합니다.

생성 과정에서 사용되지 않는 원격 볼륨이 정리되지 않는 경우가 있습니다. 추가 가져오기 작업을 시작하기 전에 시스템 상태가 최적화되어 있고 네트워크 연결이 안정적인지 확인하십시오.



== 타겟 어레이에서 내 모든 볼륨이 보이지 않는 이유는 무엇입니까?

Remote Storage 기능에 대한 가져오기를 구성할 때 블록 크기, 용량 또는 볼륨 가용성으로 인해 일부 볼륨이 타겟 후보 목록에 표시되지 않을 수 있습니다.

목록에 포함되려면 볼륨 후보는 다음 조건을 충족해야 합니다.

* 원격 볼륨과 같거나 그 이상의 용량.
* 원격 볼륨과 동일한 블록 크기입니다.
* Optimal의 현재 상태입니다.


다음과 같은 경우 볼륨 후보는 목록에서 제외됩니다.

* 다음 관계 중 하나: 볼륨 복사본, 스냅샷 또는 미러링.
* 재구성 작업이 진행 중입니다.
* 다른 장치(호스트 또는 호스트 클러스터)에 매핑합니다.
* 읽기 플래시 캐시가 활성화되었습니다.




== 가져오기에서 원격 볼륨에 대해 알아야 할 사항은 무엇입니까?

Remote Storage 기능을 사용할 때는 원격 볼륨이 데이터가 시작되는 소스라는 점에 유의하십시오.

가져오기가 진행되는 동안 데이터는 원격 볼륨에서 타겟 스토리지 시스템의 타겟 볼륨으로 전송됩니다. 이 두 볼륨의 블록 크기는 일치해야 합니다.



== 원격 스토리지 가져오기를 시작하기 전에 알아야 할 사항은 무엇입니까?

원격 스토리지 기능을 사용하면 원격 스토리지 시스템에서 로컬 E-Series 스토리지 시스템의 볼륨으로 데이터를 복사할 수 있습니다. 이 기능을 사용하기 전에 다음 지침을 검토하십시오.



=== 구성

원격 스토리지 가져오기를 생성하기 전에 다음 작업을 완료하고 다음 조건을 확인해야 합니다.

* 로컬 E-Series 스토리지 시스템의 각 컨트롤러가 원격 스토리지 시스템에 대한 iSCSI 연결을 가지고 있는지 확인합니다.
* 로컬 E-Series 스토리지 시스템에서 가져오기 작업을 위한 타겟 볼륨을 생성하십시오. 해당 볼륨의 용량이 소스 볼륨과 같거나 커야 하고, 블록 크기가 소스 볼륨과 일치해야 하며, 매핑되지 않아야 합니다. link:create-volumes.html["볼륨 생성"]을 참조하십시오.
* 로컬 E-Series 스토리지 시스템을 iSCSI 정규화 이름(IQN)을 사용하여 원격 시스템에서 호스트로 설정하십시오. IQN은 메뉴:[설정[시스템 > iSCSI 설정 > 타겟 IQN]]에서 확인할 수 있습니다. 또한 사용 중인 시스템에 따라 적절한 호스트 유형을 설정해야 합니다.
* 원격 스토리지 시스템에서 선택한 볼륨에 대한 모든 I/O를 중지하고, 파일 시스템을 마운트 해제하고, 호스트 또는 애플리케이션에 대한 할당을 제거합니다.
* 새로 생성된 로컬 E-Series 스토리지 시스템 호스트에 원격 스토리지 시스템의 볼륨을 할당합니다.
* 가져오기를 생성할 수 있도록 원격 스토리지 시스템에서 다음 정보를 수집하십시오.
+
** iSCSI Qualified Name(IQN)
** iSCSI IP 주소
** 소스 데이터가 있는 원격 스토리지 장치의 LUN 번호입니다


* 가져오기 프로세스가 시작되면 로컬 타겟 볼륨 전체가 복사된 데이터로 덮어쓰여집니다. 로컬 타겟 볼륨에 새로 기록되는 데이터는 가져오기가 생성된 후 원격 스토리지 장치의 볼륨으로 전파됩니다. 따라서 가져오기 프로세스를 시작하기 전에 원격 시스템의 볼륨을 백업하는 것이 좋습니다.




=== 가져오기 프로세스

다음 단계에서는 가져오기 프로세스에 대해 설명합니다.

. System Manager 인터페이스에 액세스한 다음 *Remote Storage* 페이지로 이동합니다. *Import*를 선택하여 새 가져오기 생성을 시작합니다. 자세한 지침은 link:rtv-import-remote-storage.html["원격 스토리지 가져오기"]를 참조하십시오.
+
오프라인 가져오기를 수행하려면 가져오기가 완료될 때까지 타겟 볼륨을 매핑하지 마십시오.

. 가져오기 진행 상황을 모니터링합니다.
+
가져오기가 시작되면 타겟 볼륨을 매핑할 수 있습니다. 가져오기 작업 완료에 필요한 시간은 원격 스토리지 장치(소스 볼륨)의 크기, 가져오기 우선 순위 설정, 그리고 두 스토리지 시스템과 관련 볼륨의 I/O 부하량에 따라 달라집니다.

+
가져오기가 완료되면 타겟 볼륨은 소스의 복제본이 됩니다.

. 매핑 관계를 해제할 준비가 되면 *진행 중인 작업* 패널에서 가져오기 객체에 대해 *연결 해제*를 수행하십시오.


가져오기 연결이 끊어지면 로컬 대상의 성능은 정상으로 돌아오며 더 이상 원격 연결의 영향을 받지 않습니다.



=== 제한 사항

원격 스토리지 기능에는 다음과 같은 제한 사항이 있습니다.

* 미러링을 비활성화해야 합니다.
* E-Series 시스템의 타겟 볼륨에는 스냅샷이 없어야 합니다.
* 가져오기를 시작하기 전에 E-Series 시스템의 타겟 볼륨이 어떤 호스트에도 매핑되어 있지 않아야 합니다.
* E-Series 시스템의 타겟 볼륨은 리소스 프로비저닝이 비활성화되어 있어야 합니다.
* 원격 스토리지 볼륨을 호스트 또는 여러 호스트에 직접 매핑하는 것은 지원되지 않습니다.
* Web Services Proxy는 지원되지 않습니다.
* iSCSI CHAP 암호는 지원되지 않습니다.
* SMcli는 지원되지 않습니다.
* VMware Datastore는 지원되지 않습니다.
* 가져오기 쌍이 있는 경우 관계/가져오기 쌍의 스토리지 시스템 중 하나만 한 번에 업그레이드할 수 있습니다.
