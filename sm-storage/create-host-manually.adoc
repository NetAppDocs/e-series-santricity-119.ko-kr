= SANtricity System Manager에서 호스트를 수동으로 생성합니다
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
자동으로 검색되지 않는 호스트의 경우 수동으로 호스트를 생성할 수 있습니다. 호스트 생성은 스토리지 시스템이 연결된 호스트를 인식하고 볼륨에 대한 I/O 액세스를 허용하는 데 필요한 단계 중 하나입니다.

.이 작업 정보
호스트를 생성할 때 다음 지침을 염두에 두십시오.

* 호스트와 연결된 호스트 식별자 포트를 정의해야 합니다.
* 호스트에 할당된 시스템 이름과 동일한 이름을 제공했는지 확인하십시오.
* 선택한 이름이 이미 사용 중인 경우 이 작업은 성공하지 않습니다.
* 이름의 길이는 30자를 초과할 수 없습니다.


.단계
. 메뉴:Storage[Hosts]를 선택합니다.
. 메뉴: 생성[호스트]를 클릭합니다.
+
호스트 생성 대화 상자가 나타납니다.

. 호스트에 대한 설정을 적절하게 선택합니다.
+
.필드 세부 정보
[%collapsible]
====
[cols="25h,~"]
|===
| 설정 | 설명 


 a| 
이름
 a| 
새 호스트의 이름을 입력합니다.



 a| 
호스트 운영 체제 유형
 a| 
드롭다운 목록에서 새 호스트에서 실행 중인 운영 체제를 선택합니다.



 a| 
호스트 인터페이스 유형
 a| 
(선택 사항) 스토리지 어레이에서 지원하는 호스트 인터페이스 유형이 두 개 이상인 경우 사용할 호스트 인터페이스 유형을 선택합니다.



 a| 
호스트 포트
 a| 
다음 중 하나를 수행합니다.

** *I/O 인터페이스 선택*
+
일반적으로 호스트 포트는 로그인되어 있어야 하며 드롭다운 목록에서 사용할 수 있어야 합니다. 목록에서 호스트 포트 식별자를 선택할 수 있습니다.

** *수동 추가*
+
호스트 포트 식별자가 목록에 표시되지 않으면 해당 호스트 포트가 로그인되지 않은 것입니다. HBA 유틸리티 또는 iSCSI 이니시에이터 유틸리티를 사용하여 호스트 포트 식별자를 찾고 호스트와 연결할 수 있습니다.

+
호스트 포트 식별자를 수동으로 입력하거나 유틸리티에서 (한 번에 하나씩) 복사하여 * 호스트 포트 * 필드에 붙여넣을 수 있습니다.

+
호스트에 연결할 호스트 포트 식별자는 한 번에 하나씩만 선택해야 하지만, 해당 호스트에 연결할 식별자는 여러 개 선택할 수 있습니다. 각 식별자는 *호스트 포트* 필드에 표시됩니다. 필요한 경우 식별자 옆에 있는 *X*를 선택하여 제거할 수도 있습니다.





 a| 
CHAP 이니시에이터
 a| 
(선택 사항) iSCSI IQN을 사용하여 호스트 포트를 선택하거나 수동으로 입력한 경우, 스토리지 어레이에 액세스하려는 호스트가 CHAP(Challenge Handshake Authentication Protocol)을 사용하여 인증하도록 요구하려면 *CHAP initiator* 확인란을 선택하십시오. 선택하거나 수동으로 입력한 각 iSCSI 호스트 포트에 대해 다음을 수행하십시오.

** CHAP 인증을 위해 각 iSCSI 호스트 이니시에이터에 설정한 것과 동일한 CHAP 암호를 입력하십시오. 상호 CHAP 인증(호스트가 스토리지 어레이에 자체 인증을 하고 스토리지 어레이도 호스트에 자체 인증을 할 수 있도록 하는 양방향 인증)을 사용하는 경우 초기 설정 시 또는 설정을 변경하여 스토리지 어레이에 대한 CHAP 암호도 설정해야 합니다.
** 호스트 인증이 필요하지 않은 경우 필드를 비워 두십시오.


현재 System Manager가 사용하는 유일한 iSCSI 인증 방법은 CHAP입니다.

|===
====
. *Create*를 클릭합니다.


.결과
호스트가 성공적으로 생성되면 시스템은 해당 호스트에 대해 구성된 각 호스트 포트에 대한 기본 이름(사용자 레이블)을 생성합니다.

기본 별칭은 <``Hostname_Port Number``>입니다. 예를 들어,  `host IPT is IPT_1`에 대해 생성된 첫 번째 포트의 기본 별칭입니다.
