= SANtricity System Manager에서 기존 볼륨 그룹 및 풀에 대한 리소스 프로비저닝 활성화 또는 비활성화
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
DULBE를 지원하는 드라이브의 경우 풀 또는 볼륨 그룹의 기존 볼륨에서 리소스 프로비저닝을 설정하거나 해제할 수 있습니다.

리소스 프로비저닝은 EF300 및 EF600 스토리지 어레이에서 사용할 수 있는 기능으로, 백그라운드 초기화 프로세스 없이 볼륨을 즉시 사용할 수 있도록 합니다. 볼륨에 할당된 모든 드라이브 블록은 할당 해제(매핑 해제)되므로 SSD 수명을 연장하고 최대 쓰기 성능을 향상시킬 수 있습니다.

기본적으로 DULBE를 지원하는 드라이브가 있는 시스템에서는 리소스 프로비저닝이 활성화되어 있습니다. 이전에 리소스 프로비저닝을 비활성화하지 않은 경우 다시 활성화할 필요가 없습니다.

.시작하기 전에
* EF300 또는 EF600 스토리지 시스템이 있어야 합니다.
+

NOTE: 현재 EF300C 또는 EF600C 스토리지 어레이에서는 DULBE가 지원되지 않습니다.

* 모든 드라이브가 NVMe Deallocated or Unwritten Logical Block Error Enable(DULBE) 오류 복구 기능을 지원하는 SSD 볼륨 그룹 또는 풀이 있어야 합니다. 그렇지 않으면 리소스 프로비저닝 옵션을 사용할 수 없습니다.


.이 작업 정보
기존 볼륨 그룹 및 풀에 대해 리소스 프로비저닝을 활성화하면 선택한 볼륨 그룹 또는 풀의 모든 볼륨에서 블록 할당 해제가 허용되도록 변경됩니다. 이 과정에는 할당 해제 수준에서 일관된 할당을 보장하기 위한 백그라운드 작업이 포함될 수 있습니다. 이 작업 자체는 공간을 할당 해제하지 않습니다. 백그라운드 작업이 완료되면 운영 체제에서 사용되지 않는 블록을 할당 해제하여 사용 가능한 공간을 확보해야 합니다.

기존 볼륨 그룹 또는 풀에 대한 리소스 프로비저닝을 비활성화하면 백그라운드 작업으로 모든 볼륨의 논리 블록이 모두 덮어쓰여집니다. 기존 데이터는 그대로 유지됩니다. 이 쓰기 작업은 해당 볼륨 그룹 또는 풀과 연결된 드라이브에 블록을 매핑하거나 프로비저닝합니다.


NOTE: 새 볼륨 그룹 및 풀의 경우 메뉴:Settings[System > Additional Settings > Enable/Disable Resource-Provisioned Volumes]에서 리소스 프로비저닝을 활성화 또는 비활성화할 수 있습니다.

.단계
. 메뉴: 스토리지[풀 및 볼륨 그룹]를 선택합니다.
. 목록에서 풀 또는 볼륨 그룹 하나를 선택하십시오.
+
한 번에 하나의 풀 또는 볼륨 그룹만 선택할 수 있습니다. 목록을 아래로 스크롤하면 추가 풀 또는 볼륨 그룹을 볼 수 있습니다.

. * 일반적이지 않은 작업 * 을 선택한 다음 * 리소스 프로비저닝 활성화 * 또는 * 리소스 프로비저닝 비활성화 * 를 선택합니다.
. 대화 상자에서 작업을 확인합니다.



NOTE: *DULBE를 다시 활성화한 경우* -- 백그라운드 작업이 완료된 후 호스트가 DULBE 구성 변경 사항을 감지하도록 호스트를 재부팅하고 모든 파일 시스템을 다시 마운트해야 할 수 있습니다.
